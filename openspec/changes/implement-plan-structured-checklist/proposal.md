# 计划结构化子任务清单

状态：实施中（2026-11-11）。来源：P3 人工验收反馈——DSH 等 coding 应用的 plan 会制定结构化子任务，本工作台此前把 plan 主要呈现为一个文本产物。

## 背景与问题

现有 Plan 从数据到执行都是结构化的：`plan.vN.json` 含 `steps[{step_id,title,kind,risk,files,depends_on,acceptance,verification,executor}]`、验收标准与验证命令；执行时有 `StepLedger`（pending/in_progress/blocked/done/deviated/skipped + 每步证据）与文件范围门禁。但用户可见的体验是：

- 审阅卡只显示「计划 v1 / 步骤 N · 验收 M」摘要，主要动作是 `Ctrl+R` 阅读 Markdown 正文；
- 执行中主区只显示普通任务与工具流，每步状态只在内部 ledger 与 `/plan` 文本覆盖层可见；
- `/plan` 覆盖层是渲染文本，不是可扫视的子任务清单。

结果是底层虽有结构化步骤，心智模型仍是「审阅一份计划文档」，与 DSH 式「制定并跟踪子任务」不一致。

## 目标

1. **审阅即清单**：计划卡与审阅焦点直接列出步骤（编号、step_id、标题、kind/risk、文件、依赖、验收标记）；`Ctrl+R` 的 Markdown 正文保留为详情。
2. **执行实时只读进度**：主区显示计划步骤清单与状态图标、当前步骤、证据数，随 `start_plan_step` / `complete_plan_step` / 工具证据更新；不接收输入、不改变执行。
3. **保留门禁与证据底座**：Plan JSON、版本/hash、批准/修订、验收命令、StepLedger 与 worktree 绑定不变；`/plan` 覆盖层与侧栏 `doneSteps` 也显示真实完成数。
4. **窄屏安全**：覆盖层/审批/阅读/窄终端下隐藏进度面板，不破坏既有布局与 32×12 可用性。

## 非目标

- 不用对话式 todo 替换 Plan 产物，不取消批准/修订/验收门；
- 不在执行中直接新增/重排/跳过步骤（本轮只读进度；可编辑留到后续增量）；
- 不改任务运行时、审批门与验收判定语义。

## 验收

- 计划审阅卡与审阅焦点出现结构化步骤行，文档正文仍可查看；
- 执行中主区出现只读进度清单，状态随步骤推进更新，结束时显示完成数；
- 侧栏计划摘要的完成步骤数来自真实 ledger；
- 全量 Python/Ink 回归通过；真实 PTY 跑通 plan demo 的「出计划卡 → 批准执行 → 审批 → 进度更新」；
- P3 人工验收在该改造完成前保持暂停。
