## 侧栏生命周期与启动噪声（2026-11-10）

手动验收反馈：重启工作台后左下角出现「找不到计划产物」；主对话退出后右侧边栏没有一同关闭；重新进入后再按 Ctrl+G 又出现一个侧栏（截图出现并排两个侧栏）。

根因与修复：

- **启动噪声**：resumed 会话在 ready 后自动查询一次计划审阅，用于展示待审计划；无计划产物时后端返回 `not_found`，TUI 把它当作反馈文本显示。现在自动发现为静默查询，无 target 的失败不再写入状态行；显式 `/plan` 或审阅入口仍提示「找不到计划产物」。
- **主区退出不关侧栏**：旧策略为「有选区时保留侧栏供复制」，`killLinkedSidebar` 与侧栏自身的父进程看护都跳过有选区的实例。反馈后改为：主区退出（含崩溃、被 SIGTERM/SIGHUP）一律联动结束侧栏，不再看选区；侧栏父进程消失即卸载。选区的复制需求仍可在退出前完成，清除或 `q` 也可随时退出。
- **遗留与重复面板**：新增 `reapStaleSidebars`：主工作台启动或再次打开侧栏前扫描同一工作区的 link 登记，父进程已退出且面板进程仍存活时 SIGTERM 并清理 signal/request/reply 通道，避免旧版本或崩溃留下的孤儿成为第二个侧栏。同时 `focusExistingSidebarForTui`：本实例已有存活侧栏时按登记 PID 让 Ghostty 聚焦该终端，标题覆盖失效也不会再开一个分屏。
- 不同工作台实例的存活侧栏仍不互相终止或回收；只有父进程已死亡的登记会被清理。
