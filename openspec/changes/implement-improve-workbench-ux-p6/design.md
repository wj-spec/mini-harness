# P6 设计

## 先建立对象身份

工作区只是文件位置，不能表示会话或正在阅读的运行。每个主工作台挂载创建随机实例 ID，与父进程号共同形成 owner；路径、启动参数、标题、登记、校准与清理都使用同一 owner。信号额外带工作区、会话 ID 与递增 revision。独立侧栏没有 owner 时仅显示工作区 diff，不展示伪绑定的本轮标记或计划。

主工作台拥有信号，侧栏拥有自己的进程登记；关闭侧栏只移除本进程登记，主工作台结束才清理自身信号。原子替换避免半写入，读取限制大小并校验 owner/工作区/revision。另一实例数据、回退 revision 和过期 owner 不应用。旧文件保留兼容读取，但不能成为跨窗口动作依据。

Ghostty 使用带实例标识的标题定位既有侧栏；首次 split 通过主进程 PID 找到来源 terminal，包装 shell 存在时使用主进程 TTY 回退，不能猜 front window。安装的 Ghostty.sdef 提供 terminal 的 pid/id/tty。尺寸校准定位同实例，窗口关闭同时核对窗口 ID、实例标题与单 tab/单 pane；用户扩展后的窗口不整窗关闭。quick terminal 是应用级共享资源：已归另一实例时提示使用 split/window，不切换或覆盖。Terminal 独立窗口沿用现有入口并修正来源窗口引用；真实 GUI 手感单列验收。

原生 Ghostty 的标题、前台进程/TTY 与窗口生命周期仍需验证；quick 同时启动和同一实例重复登记的进程互斥已补齐，见下节。文件通道和假宿主进程测试不能替代原生 GUI 证据。

### 启动与实例占用（2026-11-09）

自动启动先按 workspace/instanceId/parentPid 取得工作台占用，quick 再取得共享的 quick 启动占用。各占用只覆盖宿主动作，同一工作台不会同时创建两个 pane，不同工作台仍可各自 split；quick 竞争不等待或抢占，只返回可理解的提示。宿主执行完成后释放占用，原有标题归属检查继续负责已存在的 quick。

实际侧栏 CLI 按实际登记通道取得实例占用直到退出，相对和绝对 workspace 共用同一登记时也共用占用；它与启动占用分开，避免宿主仍在等待时拒绝自己启动的子进程。取得实例占用后再核对旧登记/父进程、设置标题和渲染，退出先清理自身登记再释放。重复进程不会改原登记，也不会清除原 pane 的标题。

占用使用准备好的非空目录原子 rename 到 active；目录内 PID/token 在换入前已写完整。活进程占用不回收；已结束的代次移到固定 retired-token 后再争用 active。代次目录保留，确保同时读取旧代的迟到清理者不能移动新占用。候选目录在 finally 清理；这些运行时记录沿用系统临时通道目录，不作为用户工作区文件提交，也不在运行期间主动清理退休代次。未知记录或 PID 探测返回 EPERM 时保守拒绝，权限边界保持原 ApprovalGate。

## 检查区对象与交互

### 内嵌专注检查（2026-11-09）

同一个检查对象有独立侧栏和主区专注两种呈现，复用 SidebarApp 及计划/变更/验证阅读器。主区按钮进入所选或当前对象；结果入口打开独立侧栏失败或不受支持时进入内嵌视图。内嵌视图提供“返回草稿”“独立侧栏”，Esc/q 返回；当前对象与所选结果仍由原 inspectionSelection 和实例信号确定。

主 Composer 保持挂载，隐藏时关闭编辑和主区鼠标处理；检查器隐藏时关闭自身及子阅读器/选区动作的输入，保留页码、位置与选区。Ctrl+C/Q 由主区统一停止/退出，不把检查对象当成控制目标。新审批显示提示，返回后仍走原审批门。工作区/会话切换销毁旧检查器，避免跨会话保留。

内嵌计划直接调用主区已有的 readPage，独立侧栏继续文件请求；二者共享已知 Ref、会话与后端能力核验，单次在途忙碌明确可重试。附回沿用既有来源、版本、去重及回执。显示不同不会增加运行/权限。只有一个检查入口时占用原状态行，不减少既有紧凑正文行数；多个入口在现有动作行并列，窄屏用“检查 / 历史 / 当前”。

### worktree 文件来源与 diff 路由（2026-11-09）

会话所属 workspace 保持为项目目录，另用 `fileSource {root, identity}` 保存实际工具目录。root 在运行开始时从 Agent 的工具根取得；identity 使用目录设备号与 inode，只做本机来源核对，不改变权限。文件来源随检查快照保存，历史读取不按当前任务元数据改写旧来源；旧格式没有来源时明确为 null，不猜测主项目。ready 与 attach task_snapshot 携带当前来源，历史选择优先使用该条保存来源。

侧栏通信仍绑定项目 workspace/owner/session，Git 读取才转到 fileSource.root。绑定侧栏在来源信号到达前不读取主项目。读取核对目录真实路径、身份和 Git 根，失效/替换/丢失 Git 根均不回退。来源切换重置同名文件的阅读/已读状态，晚返回不能覆盖另一来源。sourceKey 按字段规范化，undefined 的兼容工作区与 null 的未知来源分开。

diff 选区携带文件来源，主工作台从当前运行或已保留历史结果确定允许的来源；先核对来源，再在同一目录重读 diff 和选区。伪造主目录、来源变化或版本变化均拒绝附回并保留可复制内容，成功仍保留已有草稿/光标，不自动发送。引用文字包含来源目录，计划与验证保留原通道。

阅读页的键盘订阅保持稳定，回调根据已提交的 active 状态决定是否处理；验证组件随首份可用数据准备，避免切页后等待 passive effect 才接收首键。隐藏页不处理输入，已打开的阅读快照继续固定。

当前 diff 是该目录现在与 HEAD 的差异，不是历史内容归档。目录已清理/替换、来源未知或不是可读取的 Git 根时，变更页明确不可用，计划与验证仍可读。内嵌专注检查及完整真人旅程保持原要求。

### attach 的任务范围与离线检查（2026-11-09）

独立 attach 用绑定任务的 TaskRecord 确定会话、项目工作区与 task_id。只读检查由 `AttachInspection` 直接读取保存记录，不进入 Agent 队列；socket observer 的查询也只回复发起连接，不记录到运行日志或广播给另一连接。每页三条，计划正文只能读取本连接已选记录关联的准确 Ref，跨任务请求直接拒绝。

中继主动发送身份与任务快照，不依赖有限的旧事件回放。支持新检查能力的 socket 在回放后再发送权威任务快照，避免旧状态覆盖当前状态；同轮快照保留已收到的结果。正常结束或断线后，中继继续提供离线查询，界面显示“离线只读”、清除审批和活动控制目标，普通提交保留草稿。客户端与中继都拒绝离线执行；不自动重连、续跑或重试结果未知的控制操作。无 socket 且存在保存记录时可直接重开只读；无记录时明确报错。

该批接通历史、准确计划和保存的验证事实；后续文件来源路由见上节。历史文件名不能据此解释为主工作区当前 diff，也没有保存历史 diff；该项和内嵌专注检查仍属 P6 未完成要求。

### 重开历史结果入口（2026-11-09）

主区“历史结果”与 `/inspections` 打开独立只读视图，按当前会话分页，每页三条完整快照；不从恢复的文字消息推断对应关系。选择记录后保留准确快照，再进入已有变更/计划/验证检查页。只有明确选择才改变检查对象，当前执行 ID、草稿和取消目标不随历史查询改变。

查询先于 stdio 的执行忙碌门处理，既不占用活动任务也不授予权限；目录错误只返回该查询的错误。前端检查能力和回执身份、嵌套事实、游标前进方向；失败保页、原游标重试，关闭或换会话后不接入迟到回执。每页三条结合每记录 256 KiB 的保存上限，使响应保持在协议 1 MiB 内。缺失/损坏记录明确说明，unknown 不推断成完成。

该增量最初只接通主工作台；后续 attach 的任务过滤与离线查询见上节。内嵌专注检查仍未实现。历史触及路径不等于历史 diff，准确旧计划失效时仍沿用只读审阅的错误反馈。

### 持久检查记录与只读分页（2026-11-09）

`app/runtime/inspection.py` 在会话内按请求保存检查快照，stdio 从实际工具、任务状态、计划提交和最终结果填入事实。请求/追踪 ID、任务/段与完整计划 Ref 分开保存；修订额外保存来源与准确产物。普通运行没有持久任务时保持空值；没有最终回执的记录保持 unknown，不能把旧命令或模型文字当作完成证据。

记录以 UTF-8 字节和条目数限量，原子替换并校验内容摘要；最终保存失败有提示。只读 `read`/`page` 支持准确请求、原任务过滤和稳定游标，拒绝重复身份及损坏记录；读取不写任务、不调用模型、不审批或执行。文件列表仅为触及路径，历史 diff 不在本批保存范围。

这层目前接通后端保存和 Python 只读 API；下一步由结构化只读协议接到历史结果与独立 attach，显式选定原请求后进入既有检查页。前端不得因恢复而自动启动任务或替换当前运行/停止目标。完整结果旅程、内嵌专注检查和真人验收仍在清单中。

### 已实现的运行与计划投影（2026-11-09）

视图独立保存 inspection，结束后的费用等查询不会替换它。请求 ID 对应 stdio 请求及 TaskRuntime 的段记录 run_id；Agent 追踪 ID 来自该请求的 context_snapshot/done，是另一种标识。task_state 提供持久任务与段号；同请求不能被另一任务或更早段覆盖。普通输入未创建 TaskRecord 时，任务/段号保持空值。新请求即清空前轮文件与验证；成功文件标记只从准确请求 ID 筛选。

Plan 快照来自经请求匹配的审阅回执，保留完整 ReviewRef（会话、计划任务、计划 ID、版本、哈希），区分审阅、规划产物和执行绑定。执行的 begin 直接承接 launch；续做只有 task_state 的任务、plan_id/version 与既有审阅对象一致才重新绑定，不能沿用旧段验收。普通状态刷新完整发布快照，避免清除计划；未读取步骤进度时显示未知。旧版按文件时间和版本号跨任务拼接的侧栏摘要已移除，旧版主区 /plan 阅读仍保留。

重开会话不从 tasks 提示或历史工具消息猜测运行；可独立展示审阅快照。明确 attach 时只使用该 task_snapshot 的范围，尚未读取的结果保持未知。修订任务到新版产物、独立 attach 的完整结构化结果、固定阅读下的新对象提示仍归下一切片，不能用本增量代替三类检查页和附回验收。

### 固定阅读与当前验证记录（2026-11-09）

打开计划摘要或验证记录时保留内容与对象范围；后台更新只提示，`r` 显式接入，Esc 返回变更。相同计划切到新运行段也算对象更新；当前已无计划/运行时保留旧阅读快照。进入阅读停止文件自动跟随，返回时保留原变更位置。验证正文支持分页、首尾与按源行缩放保位。

验证记录由当前请求的结构化结束结果与命令执行事实组成，显示三态验证、完成判定、命令、实际退出码和输出。普通命令与显式验证命令分开标记；文字声称成功不能覆盖非零退出。最多保留最近 20 条命令，每条输出 2000 字符，省略及截断明确提示，完整工具记录留主区。信号校验请求归属和执行状态/退出码一致性，不接收错轮结果。

真实链路发现 harness 可信验收不经过 Agent 工具事件；现由 stdio 在验收结果返回后发布同一请求的结构化 tool_result，计划与 goal 共用。写入/命令仍经原 ApprovalGate；拒绝的命令标记 unknown 与原因，不能宣称执行过。整组验收超时/取消未得到结果时仍保持未知。此增量不提供完整历史/独立 attach 证据加载、计划正文分页、结果入口和附回；完整 P6 清单保持。

### 计划正文与只读请求通道（2026-11-09）

准确 ReviewRef 的计划页按需读取正文，使用后端既有 `plan review` 分页接口。侧栏请求与主区审阅卡状态分离，回执不会改变当前运行 ID、焦点或草稿。主区仅接受当前会话中已知的计划身份；侧栏按原请求 ID、会话、owner、完整 Ref 和 Unicode 偏移验收结果。后端仍负责拒绝已失效版本与哈希，不从最新文件猜测正文。

每个 owner 使用独立 request/reply 文件，原子写入、256 KiB 上限，正文每页最多 16000 Unicode 字符。请求限时，主区同时处理一页并保留至多 64 条已处理 ID；客户端取消只清理自己的请求，主区退出清理该实例的两类文件。回执身份不匹配、断线、忙碌或超时均保留原页，用户可重试。该通道只承载计划读取，不接受执行、授权或附回草稿动作；同 owner 多个侧栏竞争尚未提供多消费者保证。

正文按原始行换行与缩放保位；上下页、重试和返回可点击，方向键与滚轮保留。当前页在下一页请求期间保持可见，失败仍显示原内容。页码位于标题前部，32 列下可见。新对象提示优先于加载状态，显式接入后旧回执不能替换新内容。已加载页面保留快照，其余页必须通过原 Ref 查询；旧版本失效时显示原因。

### 可点击检查页导航（2026-11-09）

顶部常驻“变更 / 计划 / 验证”，当前页同时以 `›` 和颜色标识；32 列显示完整标签，极窄窗口缩为单字。点击或原有 p/v/Esc 切换页面。三页分别保留快照与阅读位置，已读入的计划页不因切换而重新请求；隐藏页停用键盘/鼠标处理，但仍可完成已发出的只读查询。当前仅保留各页最近一次打开的对象，历史结果入口另行实施。

新计划/验证只提示，点击“接入”才更新；首次到达空页的数据可以直接显示。变更页有新版 diff 时“接入”更新当前文件；只有其他文件活动时显示“跟随”，回到最近触及文件，避免提供没有内容可接入的动作。缺少记录或未绑定主会话时解释原因，入口仍可返回变更。

导航的点击使用真实布局范围和按下/抬起配对，缩放或动作含义变化后不接受旧按下位置。三个内容页只启用当前页的鼠标订阅，共用顶部导航处理；计划和验证的滚轮范围计入导航行偏移。顶部占用一行正文空间，不叠加新的模式状态栏。

1. 运行范围：从权威事件投影 task、run、segment；空值明确，不猜最新文件。结束保留该轮范围，恢复只读。计划快照带 plan/version/hash，普通状态刷新不清掉有效摘要。
2. 检查内容：变更始终标记工作区 vs HEAD，可筛本轮触及；计划与验证读取同一范围的结构化结果，不解析自然语言。主区结果可进入侧栏或主区专注阅读。
3. 已读与附回：已读绑定 diff revision；附回消息绑定来源范围/版本和 request ID，保留原草稿、只附不发送、回执去重。断线/过期/错对象保留选中内容并允许复制。

## 验证接口

沿用现有 App/SidebarApp 输入与渲染、信号/登记文件公共读写、host runner 和实际子进程 seam。先用同一工作区两个 owner 复现串台，再验证清理、不同会话、损坏/迟到信号；实际 PTY 验证两个侧栏退出互不影响。AppleScript 编译与参数匹配检查不能代替 Ghostty 真人操作。

不增加通用消息框架、跨工作区服务或模型权限。各切片先测试、再实现、评审及全量验证；实例产物留 `.vibe/ux-p6-scope-2026-11-08/`，投影产物留 `.vibe/ux-p6-projection-2026-11-09/`。沿用 App/SidebarApp、reduceView、真实后端和文件通道公共验证接口，不以私有函数断言代替旅程。


### 主区结果入口与同轮快照（2026-11-09）

结束或断线时将当前请求的 inspection 保留在原结果条目，包含会话/工作区、运行范围、准确计划、验证事实和触及文件。按钮元数据与条目身份一起渲染；普通正文相同文字不构成动作。选择结果仅改变侧栏投影，不改变执行 ID、审批和草稿。主区“回到当前”显式解除固定，覆盖层期间隐藏该入口。

导航是绑定实例信号中的 UUID、已知页面与 result/current 模式。新 UUID 才切换侧栏对象及页面；同 UUID 的后续刷新不抢走手动选择页。晚到计划回执按准确任务/请求补入原条目的缺失计划，选中投影跟随该条目补齐，其他计划查询不覆盖。变更内容仍是当前工作区相对 HEAD 的 diff，所选结果只提供文件标记。

快照仅在进程内保留，不从重开后的普通历史文本猜身份。持久化历史证据、独立 attach、内嵌专注检查与附回仍是后续范围；未知宿主由既有启动入口提供手动命令。


### 选区附回与回执（2026-11-09）

变更和验证共用按源行/字符偏移的选择逻辑，空行保留屏幕行高。拖选 diff 时停止跟随；选区保存不可变的来源版本、会话与原请求，后续显示变化不改写引用。复制与附回始终是显式按钮，窄栏按行排布。

专用 draft-request/draft-reply 通道与计划只读请求分离，唯一动作 append-excerpt。接收端限定 owner/workspace/session、已知请求、30 秒消息有效期、32KB 选区和相对路径；diff 重读 Git 对照版本及选区，验证从原请求事实重建。只向普通主区草稿追加引用文本，保留已有输入和光标，不进入审批或后端执行接口。记录最近 35 秒的成功/失败回执，重试原 ID 返回原结果；同 ID 不同内容拒绝，单次在途处理避免乱序。

选区存在时，侧栏登记 hasSelection，主区退出保留该侧栏及窗口；父进程失联后显示只读保留，清除或 q 才退出。正常无选区仍随主区清理。失败保留选区，显式复制可带原版本回退；未发送草稿与选区暂不持久化。计划跨页选择、diff 已读、多个同 owner 消费者和原生 GUI 保留验证继续待做。


### 计划跨页选区与版本已读（2026-11-09）

计划引用扩展既有 draft 通道，以完整 ReviewRef、原文 Unicode cursor/length 和 plan_hash 绑定来源；显示坐标先按可见字符映射回原文，制表符展开、中文和 emoji 不改变来源偏移。start/end 保留通用选区展示字段，计划校验以 cursor/length 为准。侧栏缓存最近三页，续选拼接连续原文，不添加分页换行；最多 32000 字节，范围或缓存不足时保留原选区并提示。

主区复用独立只读计划读取器，逐页重读所选范围后比对可见引用文本。每页最多 16000 Unicode 字符，必须前进且偏移连续；一页在途、10 秒超时，原消息 30 秒有效期和成功/失败去重保持。绑定运行的计划必须对应原结果；单独审阅计划可以没有 request ID，但必须是本会话已知 Ref。读取不替换主区卡片或运行取消目标，不增加模型调用、执行或授权。

diff 已读是当前实例/会话内的 path→revision 标记，至多 200 个文件。显式点击标记/撤销，按当前渲染版本及布局核对按下/抬起；新版不会继承旧标记，固定旧版时提示“新版未读”。截断、空或失败内容不提供完整已读动作。标记在原 footer 行显示，不增加固定高度；不会改变验证结论。标记、选区、未发送草稿均不持久化，完整结果恢复/attach 和专注检查继续待做。


### 修订运行与准确产物关联（2026-11-09）

经修订控制器匹配原请求/反馈后的回执，向检查投影提供 revision_id、来源 Ref、结果 Ref 和 task/run/segment。开始修订即绑定来源，提交后目标换为准确产物；结果摘要由原 Ref 的独立审阅回执补齐，不能借用来源标题或任意最新计划。RunInspection 和进程内结果快照保存同一来源链，普通新任务开始时清空当前绑定。

更新只接受相同会话、原来源哈希、修订 ID、任务、段和请求 ID，产物须为同族 v+1；已确认产物不能被旧运行回执或冲突哈希覆盖。查询回执可晚于 done 或下一任务，仍按原运行 ID 补原快照；主区卡片、草稿、执行取消目标保持。已打开侧栏正文依旧固定，接入动作才更换为结果。

关系明确区分 revision-source/revision-result，侧栏信号要求有绑定运行及段号；正文标题在 32 列仍可辨认。修订产物只代表计划发布，验收字段不从修订成功推导。该增量仅处理本进程内已启动的修订及显式续做；持久历史结果、重开查询后的检查入口和独立 attach 不由消息文本猜测，继续待做。
