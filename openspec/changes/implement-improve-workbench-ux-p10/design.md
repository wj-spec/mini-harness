# P10 设计

## 事实与取舍

当前阅读区由 `transcriptLines` 从 `ViewState.entries` 渲染；entries 已有 kind/text/call/output/ok/runId，但工具条目没有副作用层级，任务条目没有终态。`session/rounds/*.json` 账本存在，但把 round 记录映射回渲染行需要额外交接（run_id 只在部分条目上），本批不引入，先以「用户任务轮次」为轮次单位。

取舍：搜索/定位全部在 TUI 本地完成，不新增后端搜索协议——当前会话正文已随历史回放加载；跨会话检索需要后端索引，单列下一批。折叠只用于展示；entries、JSONL、audit 与 `/evidence` 不变。折叠依赖后端提供的工具层级，旧后端宁可不折叠也不猜测副作用。

## 轮次与错误的定义

- 轮次：一次用户任务（`begin` 产生的 task 条目）。`begin` 时记录 `runId`；`done` 时把该轮 `runStatus` 标为终态（done/error/cancelled/stopped/truncated），进行中显示「进行中」。
- 错误：工具条目 `ok=false`（调用错误、非零退出、超时）或轮次 `runStatus=error`；按渲染行顺序排列。cancelled/stopped 不算错误（用户主动）。
- 定位目标：条目在渲染结果中的**第一行**。搜索则直接定位命中行本身。

## 折叠规则

可折叠条目必须同时满足：kind=tool、有 call、`tier=read`、`ok=true`、无 pending/uncertain/execution、无 inspection 动作、且不是当前选中的工具。连续 ≥2 条折叠为一张摘要卡（`连续 N 个只读调用 · 已折叠` + `read_file×2 · grep×1`），保留原始调用证据：

- `Tab` 循环工具时选中其中一条会展开该条（其余仍可折叠）；
- `Ctrl+O` 详情页读取原始 call/output；
- 折叠卡不产生 inspection 动作行（只读工具通常无附加检查）。

## 定位面板

统一面板（查找/按轮/错误共用）：标题 + `n/m · 行号` 状态行、结果列表、按钮 `[上一条][下一条][定位][返回]`。↑↓ 选择、Enter 定位、Esc 返回；鼠标点击按钮。定位动作：写入回看位置（`follow=false`，目标行上方留 2 行），关闭面板并提示「已定位到第 N 行；Ctrl+End 回到最新」。不改变草稿、光标、审批与停止目标。

## 性能

搜索只遍历已渲染行（O(行数×子串匹配)），结果上限 200 条；列表渲染沿用 `textLines`。基准：构造 3000 条记录（约 9000 渲染行）的会话，20 次搜索取 p95；门槛 < 100ms（交互级），实测值记入验证记录。

## 协议与兼容

- `tool_call` 事件新增可选 `tier`；Python 侧在工具调用事件中带 `agent._tool_tier(call)`，异常时省略。
- TypeScript 严格校验 `tier ∈ T0–T4`；未知/缺失按「不可折叠」处理。
- 无新能力协商：旧后端仍可用 `/find`、`/rounds`、`/errors`，只是不折叠成功只读工具。

## 跨会话检索与账本深链（第二批）

- `search` 命令只扫当前工作区、当前用途（user/test）的会话消息事件；结果带 identity 以便复用显式打开的身份复核；20 条/页 + 用途作用域绑定的游标；损坏记录/会话计数，扫描超限标记 truncated。
- `/history` 打开命中面板，打开会话复用 P8 候选后端流程；打开成功后新工作台以 `initialFocus` 在历史回放完成后自动定位首个匹配行。
- `rounds` 命令只读当前会话 rounds 账本（上限 50 轮），字段防御式校验、损坏计数；TUI 按目标文本映射正文轮次，映射不到时提示用 `/sessions` 核验。
- 每次分页重新扫描会话文件，未建索引；大工作区需要后续索引/缓存批次。
