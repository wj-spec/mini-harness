# P9 授权解释与撤销

U07 的核心问题是用户只能看到「已授权数量」这类文本，无法回答：当前权限**来自哪里**（档位/进程临时授权/持久策略）、**还能用多久**（本进程还是持久文件）、以及**撤销某一条后还剩什么**。

本批不改审批判定与硬边界，只把权威状态结构化展示，并开放**进程内临时授权的逐条撤销**；持久策略文件与审批档位仍按原规则工作。

完整交付目标（P9 阶段）：用户能查看当前有效权限来源、有效期与撤销后的剩余权限，并通过后端权威接口撤销。本批先做可撤销的进程内授权（workspace / session）与只读的档位、持久策略说明；随后补上**用户级持久规则撤销**（保留 project 只读，因为撤销会放宽权限），需文件原子写回与二次确认。

## 范围

- 新增后端结构化命令：`permissions` 带 `args` 返回 `permission_overview`；不带 args 保留原文本命令（兼容旧客户端与 `/permissions reset`）。
- 概览内容：当前档位与来源（CLI 本进程 / user 策略默认 / 默认 ask，含 project 上限）、进程内 workspace 授权、进程内 session 精确授权（逐条 id、工具、目标摘要、作用域、有效期）、持久 user/project 策略规则（来源文件、规则摘要、不可进程内撤销的原因）、策略加载错误。
- 逐条撤销：按稳定 grant id 撤销 workspace 或 session 授权；未知/过期/跨工作区 id 返回明确错误；撤销回执携带 `revoked` 与撤销后的完整概览（剩余权限）。
- TUI：`/permissions` 打开结构化面板（可点击选择与撤销、显示剩余权限）；`/permissions reset` 保持 P1 文案与语义；后端不支持新协议时回退旧文本结果。
- 项目级策略写回/撤销：project 只能收紧，撤销会放宽权限，保持只读（需修改仓库文件）。
- 不做：跨进程授权同步、撤销动作独立审计文件、审计 UI（沿用 audit.jsonl）。

## 预期结果

不增加任何自动放行路径；撤销立即生效于后续工具调用，且由后端 `ApprovalGate` 作为唯一权威。所有自动测试与 fake PTY 证据之外，真人/真实终端验收单列。
