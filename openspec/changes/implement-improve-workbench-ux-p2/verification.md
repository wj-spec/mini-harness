## Shift+Enter 换行（kitty 键盘协议）（2026-11-10）

手动验收确认输入框换行方式：`Ctrl+J` 一直可用；`Shift+Enter` 过去只在终端主动上报可区分的 modified Return 时生效，实际多数终端（含 Ghostty 默认）把它当作 Enter 提交，因此文档只能写“终端支持时”。

本批在 Ink 渲染时开启 kitty 键盘协议自动探测（`kittyKeyboard: {mode: 'auto', flags: ['disambiguateEscapeCodes']}`）：

- 终端支持协议（如 Ghostty）时自动启用，`Shift+Enter` 以 CSI-u 序列上报，输入框按 `Shift+Enter` 插入换行；`Enter` 仍发送。
- 不支持协议或非交互 TTY（测试、重定向、其他终端）时自动放弃检测，行为与之前一致：`Ctrl+J` 换行、`Enter` 发送；不额外报错或阻塞输入。
- Escape/Ctrl 等组合键由协议消歧后仍解析为既有 key 语义（`key.escape`/`key.ctrl`），面板返回、Esc 草稿保留路径不变。

## 侧栏附回占位与输入换行修复（2026-11-10）

手动验收反馈：右侧栏选区点击「附回」后，输入框难以继续换行/续写；且整段多行引用直接铺满草稿。复现确认两个原因：

1. 附回把完整多行引用（标题、来源目录、逐行 `> ` 引用、`[引用结束]`）直接写成草稿文本，输入框被撑满；
2. 输入框对外部写入保留原光标，空草稿时停在开头、有草稿时停在原字符位置，于是换行/续写落在引用块之前或中间，看起来像「无法换行」。

修复：

- 附回只写入一行占位：`[附回] 工作区 vs HEAD · path · 第 N–M 行 · K 字符`（计划 `[附回] 计划 id vN · 字符 a–b · K 字符`，验证记录 `[附回] 验证记录 · K 字符`）；完整引用不进输入框。
- 完整引用保留在附回缓冲，**在真正提交时展开**给模型：普通任务、运行中纠偏、排队后续消息、`/chat` `/act` `/plan` 与目标模式启动都按提交时展开；输入框与对话卡片保留占位。
- 外部写入草稿（附回、命令预填、拒单恢复）统一把光标移到末尾，用户可以继续换行与续写；草稿内容本身不被改写。
- 附回占位不再自动发送；来源版本/请求复核、去重与错误回执保持原语义。

## 工作台记录与对话主区分离（2026-11-10）

手动验收反馈：工作台记录（复制/定位提示、命令结果、操作异常、后台提示等）作为卡片插入模型对话的专注区，会打断阅读心流。本批把提示从对话正文中移出：

- 普通工作台提示进入独立记录缓冲（`ViewState.notices`，上限 200 条），不再生成对话条目；提示也不再触发「跳到最新」，向上回看时收到提示阅读位置保持不变。
- 对话正文只保留用户任务、Agent 回复、工具记录、审批记录，以及运行回执（`[运行结束]`）、计划审阅卡与历史结果卡等结果对象。
- 底部提示行显示最新一条记录的首行（含条数）与 `/logs` 入口；审批、审阅、修订、计划/上下文/详情等按键提示优先于记录行，避免遮住当前操作说明。
- 新增 `/logs` 只读记录面板：完整多行内容、↑↓/PgUp/PgDn 滚动、Esc/Enter 返回；草稿与光标保留。记录为空时说明「操作提示与命令结果会记在这里」。
- 命令结果与后端 notice/diagnostic 同路径进入记录；`/permissions` 面板、任务/历史面板等既有结构化交互不受影响。

## 增量自审

使用 ponytail-review 方法由主代理检查实际基线增量、调用方及真实 Git 路径；这是自审，不宣称独立模型评审。负载假设：个人本地仓库、一个主会话/一个侧栏、单次 Git 读取超时 2 秒、输出上限 4 MiB。

| 发现 | 后果 | 处置 |
|---|---|---|
| 路径覆盖层没有固定对象 | 查看完整路径时新事件将对象换走 | 打开即固定，返回保留对象；回归通过 |
| 旧查询异常未核对选择版本 | A 查询迟到抛错，污染 B，甚至把 B 新内容留在待接入区 | 成功/异常均核对选择版本；回归通过 |
| 截断仅在正文末尾说明 | 首屏看起来像完整 diff | Snapshot 保留 truncated，状态行前置显示；回归通过 |
| 无 HEAD 的 staged 新文件按普通 unstaged diff 查询 | 首次提交前新内容漏显 | 使用空基线读取；真实 Git 红绿回归 |

测试夹具也修正两项错误假设：同内容删除/重命名可被 Git 识别为另一条 rename，因此改成互异内容；真实 diff 的 index 对象 ID 会随隐藏尾部变化，因此只比较去除 index 元数据后的可见前缀。未把夹具问题当产品修复。

## 性能门槛与测量

门槛已在实现前锁定：更新可见最大 1500 ms；普通/大差异输入 p95 各不超过 100 ms；两份保留 diff 原始文本总计不超过 4 MiB UTF-8。
固定机器 Apple M5 Pro / darwin arm64 / Node 24.16.0；普通 206 个跟踪文件、27 个变化，大差异另有已跟踪的 5000 行中文文件。

- 更新时效：独立线程写入，普通/大差异 × 跟随/固定 × 6 个不同轮询相位，共 24 次，全部观察到变化；最大 **1001.43 ms**，通过。`update-delays-after.json`。
- 输入响应：基线普通 p95 **14.88 ms**，大差异 **486.42 ms**；最终普通 **6.45 ms**、大差异跟随 **17.62 ms**，各 100 次、零超时，通过。证据 `ui-after.json` / `ui-large-after.json`。
- 保留文本：生产读取最多 2000 行/400000 UTF-16 单元加截断说明，单份 UTF-8 最多约 1.2 MB，两份低于 4 MiB；真实中文大文件的前后两版有字节断言。只保留 shown/pending，没有按全仓库缓存。Git 输出上限 4 MiB 与缓存门槛是两种边界。

响应测量使用真实 Git 与 Ink 渲染器，输入由独立 Worker 发出，记录可见焦点/跟随状态；超时另记，不当作成功。大差异复测显式开启跟随，让背景变化持续进入渲染。上述测量不包含 Ghostty 合成器、输入法和人类手感；不是 RSS 上限。
