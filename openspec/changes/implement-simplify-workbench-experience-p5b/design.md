# Design
## Scope
5.B 为新目标提供总段数、总时长、总 token 和估算总费用设置。预算在段开始前核对，已开始的一段沿用单段限制；累计用量可能在一段内越过总预算，费用不是服务商硬上限。
## Decisions
- TaskRecord 的扩展字段 goal_limits 为每个目标的不可变快照，created_at 为起算时间；旧 schema 可读。不更改 goal 的验收状态机。
- 新任务由后端默认创建快照，客户端不能通过 run 参数放宽。旧任务在锁内优先迁移 taskId/objective 匹配的 goal.json；否则采用匹配 GoalRecord 已知非零预算并补启动默认（旧零值也表示未记录，不能据此取消启动保护），完全缺失则固定启动默认并提示。无效已存在快照拒绝，不静默重置。
- TaskRuntime 在 start_segment 之前检查段数、墙钟时长、BudgetLedger 累计 token/费用；所有 run/task、/resume 和 worker 子后端共用。超限不创建新段、不发模型请求，手动恢复不重置上限。
- worker 续段决策优先任务快照；旧任务由子后端固定快照。GoalRecord 投影同步预算，前台从 task_state 对齐运行段的预算、起点与段前用量；恢复时不自动启动。
- 复用 settings 协议，scope=goal 仅接受四项目标字段；默认 scope 继续兼容单段。审批保存沿用 .env 版本复核、原子写入与 0600；环境覆盖优先于本次应用，应用仅影响未来新目标。
- 设置页 g 切换单段/目标分组，两份草稿分别保留、离开时保护；保存/应用反馈标明范围，最小 32×12，原模型/权限导航保留。
- 新目标默认不影响已存在目标或旧后台进程；转入后台的目标按任务快照核对。后台恢复累计状态以账本为准。
