# P1 行为与实施约定

依据：[路线图设计决策 2](../../roadmaps/improve-workbench-ux/design.md#决策-2动作焦点与输入焦点显式分离)。

## 焦点和审批

- 审批请求显示预览，草稿仍可编辑。`Ctrl+R` 显式进入审批；到达新请求不自动授权。
- 审批焦点下 y/s/p/n 或方向键只选择后端允许的范围；Enter 确认。初始没有默认授权选择。
- Esc 返回草稿；Ctrl+C 请求停止；Ctrl+Q 退出仍走既有生命周期。粘贴和按键 release 不产生审批。
- 每个选择绑定 approval id。新请求清空选择；重复事件不能重复授权，过期/已响应请求不再发送。
- Plan/工具详情不能抢走工具审批键路。审批焦点、选择范围和发送状态可见；送达异常保持可恢复状态。
- 审批可用最小尺寸 32×12。更小时只显示调大窗口和安全停止/退出，不启用授权动作。
- 审批选项独占提示区，不与 Plan/Goal 前缀竞争宽度；32×12、80×24、120×40 均验证。

## 输入受理

| 状态 | 普通输入 | 后端命令 | 本地快捷操作 |
|---|---|---|---|
| idle | 提交任务 | 按参数/能力校验后发送 | 维持原有能力 |
| running | 既有纠偏；命令型运行不接普通纠偏 | 不支持并发的命令明确未执行，保留草稿 | 复制/阅读/帮助等本地操作保留 |
| starting/stopping/waiting_approval/closed | 保留草稿；Enter 解释为何未发送 | 明确未执行，不排隐形队列 | 安全复制、停止/退出按现有生命周期 |

`disabled` 的编辑器仍允许草稿编辑；阻止提交时需通知用户。同步发送异常保留输入；已受理但结果未知必须以未知反馈，不能宣称配置成功。
授权徽标只依据后端状态更新。`/permissions reset` 明示撤销当前工作区的本进程授权，档位和持久策略仍有效。

## 检查与边界

按纵向行为逐个补红测再实现；相关 App 输入回归、审批/状态测试、stdio 权限测试和全量回归分别记录。
真人 Ghostty 的中文输入法、连续键与审批交错独立登记；模拟输入与 PTY smoke 不能代替真人体验。
本阶段完成代码评审后才能进入后续切片；整体目标保持 active，后续九阶段不随 P1 完成而消失。

## 真人反馈后的审批按钮增量（2026-11-08）

用户确认 P3 功能旅程无问题，但认为依赖快捷键的审批体验很差；恢复开发后优先改善此高频操作。
以下替换上文以 Ctrl+R 为主要入口的呈现约定，保留草稿保护、准确请求绑定和后端 Gate 语义。

- 预览下方固定显示可点击的「允许本次」「拒绝」「更多授权」；更多授权展开后才显示本进程精确规则/工作区范围及返回。
- 鼠标在同一请求、同一按钮内按下并松开才触发；拖动、旧请求、缩放后旧坐标、粘贴中的鼠标序列不提交。
- 默认焦点在草稿。Tab/Shift+Tab 进入按钮并可返回草稿，方向键选择，Enter 确认；焦点可见。Ctrl+R 与字母选择保留为辅助入口。
- 同一决定只发送一次。发送中、拒绝/允许回执与失败分别呈现；不把已发送当工具执行成功。
- 复用现有 App 终端输入→后端协议 seam、真实 PTY→fake Python seam，沿用已约定的公开行为测试边界；不测试组件私有状态。
- 在 32×12、80×24、120×40 核验按钮/停止入口、预览与草稿；自动验证、工具 PTY、Ghostty 真人分别留证。
