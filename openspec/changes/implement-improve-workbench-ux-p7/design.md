# P7 设计

## 对象和控制

后续消息尚未发给后端，不是 TaskRecord，也不是后台计划队列。每条有稳定 ID 和正文，FIFO 次序不因编辑改变。有会话路径时，发送前先把队首原子记为带请求 ID 的已发追踪记录，匹配终态后移除；没有会话路径的兼容入口仍仅在内存保存，发送同步失败保留；后端已开始的任务继续使用原取消/审批机制，不伪称可以撤回。

一个前端模块管理待办、暂停原因和显式继续；公开 App 是行为测试入口。结果判定使用匹配当前 run 的结构化 done，不从输出文字猜测：status 非 done、verified=false、completion.allowed=false 以及等待计划决策时暂停。verified 缺失/null 本身表示没有验证结论，不把纯文字成功等同失败；没有终态的断线保持结果未知。实际验证命令失败也必须暂停：无写入时 done 可能为 verified=null/allowed=true，不能抹去工具退出码；只有最终权威 verified=true 才覆盖已修复的失败。迟到/重复 done 不推进另一个队列。目标模式优先使用原控制，不能并发启动后续。

## 交互

有待办时主区显示“后续 N”按钮，`/followup` 无参数打开同一管理页，带正文保持兼容。查看即暂停自动续发，避免阅读/编辑中的项目突然消失。分页选一条，显示完整正文，可点击编辑、撤回、继续或返回。编辑独立 Composer，保存只更新待办；取消保留原文。返回原草稿和光标，Ctrl+C 仍针对当前运行，审批到达提示返回处理。

继续在可启动状态只受理队首一次；当前仍运行则恢复成功后自动推进。取消、错误、预算停止、未通过验收和断线保留剩余待办。纯粹关闭管理页不恢复自动执行。32×12 和 80×24 使用同一套动作，鼠标为主，键盘为补充。

## 生命周期与分批边界

第一批先接同一前端进程内管理、暂停策略和断线保留；退出时若仍有待办必须明确提示，不静默丢弃。第二批接会话范围的持久待办和恢复：恢复默认暂停，同会话多工作台不能覆盖或重复发送；发送与落盘的中断必须表示未知，不能自动重发。存储范围与接收确认机制在该批以实际后端协议补细，未实现前明确“仅本次窗口”。不将待办落盘视为执行授权。

## 验证和评审

使用既有公开 App/client 和实际 Node/Python PTY，不测试 hook 私有状态。依次覆盖失败后保留并编辑/撤回/继续，成功 FIFO，取消/断线/迟到终态，运行和审批中管理，发送失败，窄屏/中文光标及退出提示。恢复、多实例与真实终端完整旅程单列，不用假 Client 代替保存/重开证据。每批保存原工作树基线和范围差异，完整回归后同步里程碑。

## 持久待办与发送记录（2026-11-09）

待办属于会话；attach 另按绑定任务分域。会话目录内保存版本化 JSON，包含准确工作区/会话/任务范围、稳定消息 ID、正文、暂停原因和最多一条已发请求记录。整体原子替换，大小有界，损坏或范围不匹配不覆盖。

同一持久队列只有一个写窗口，沿用已有进程占用机制；其他窗口只读，不能编辑或继续。可点击“接入”刷新并在原持有者退出后取得占用，接入始终暂停。只读窗口不在退出时清理他人的记录。不是权限隔离，不改变 ApprovalGate。

每次添加、保存编辑、撤回均先落盘再反馈成功；写失败保留原输入并暂停。发送先把队首移至带预分配 request ID 的发送记录并落盘，再用同 ID 调用原 run 传输。收到匹配 done 才移除发送记录；旧回执不得清除新请求。中断、发送异常或保存终态失败都保留为待核对，不自动重发。

恢复默认暂停。有未确认发送记录时禁止继续队列，记录显示原正文与请求身份；可进入历史结果核对，再显式移出这条追踪记录，移出不会停止或重发原任务。当前还在运行的已发请求不能移出。未发送待办可继续编辑或撤回。退出成功保存的待办不丢弃；保存失败仍明确说明本地未保存状态，不用“已保存”掩盖错误。

该批在公开 App、BackendClient 及实际进程/终端核验：重开不执行、单写者竞争/接入、坏文件与保存失败、发送前落盘、发送后中断、迟到 done、准确请求身份。存储仅供本机用户工作流，不承诺机器断电后的 fsync 级耐久性。

实现细节：队列文件为会话目录内的 `followups.json`，attach 使用任务 ID 的 SHA-256 后缀。同会话规范目录共用单写者占用；100 条、单条 64 KiB、总文件 256 KiB 为当前上限。坏文件、非普通文件、范围不符和目录身份变化均拒绝覆盖；未保存编辑单独参与退出提示。错误回执也将已发追踪记录转为待核对。历史页显示原请求 ID，但当前没有自动对账或自动补发。
