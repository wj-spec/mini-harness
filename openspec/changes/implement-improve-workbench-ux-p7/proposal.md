# P7 后续消息控制

立项时 `/followup` 只把字符串放在内存：取消丢弃，其他 done 一律续发；用户看不到队列，也不能编辑或撤回。改为用户可检查的待办，失败后暂停并由用户决定继续，成功按明确策略推进。后台 Plan `/queue` 保持原语义。

依据：[路线图](../../roadmaps/improve-workbench-ux/roadmap.md#p7--后续消息控制)、[设计决策 5](../../roadmaps/improve-workbench-ux/design.md#决策-5明确命令模式与队列的语义)。P6 原生/真人未验收，但不构成 P7 控制语义的技术依赖。

交付包含主区可点击入口、完整内容阅读/编辑/撤回/继续、权威终态暂停、草稿及控制目标保持、断线与退出恢复范围、自动和真实终端证据。分批推进；进程内控制与会话持久恢复已有实现，工程证据和真人完整验收分别记录，P7 整体仍未验收。
