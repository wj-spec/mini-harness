# P8 设计

## 事实与取舍

第一批开始时，`/task`、`/approvals` 是文本命令；ready 的 TaskHint 不含目标与更新时间。原 `/attach now` 用固定 sleep 后重启，会直接退出当前 App，缺少连接成功确认、草稿移交与运行中退出处理；第二批已替换。SessionStore 已有按用途隔离的只读索引与打开 API。没有命令使用频率遥测，不能把源码入口数称为真实使用频率；按 U09 及用户的审批体验反馈，先贯通当前任务到审批所在对象。

## 范围与权威

任务目录只查询当前后端绑定的 workspace/session，按创建时间和 ID 稳定分页。保留完整目标（TaskRecord 上限 4000 字符）、任务状态、worker 状态/心跳异常/本机 PID/异机事实、待审批数、更新时间。异常 worker 与无 worker 分开，损坏条目明确计数，不把读取失败伪装为空目录。查询不能 recover、改任务状态、创建运行段、调用模型或处理审批。

只读请求与当前 run 独立关联，审批中仍可查询。新能力显式协商，旧后端保留原文本命令。任务选中后历史查询始终带该 task_id；看别的任务不改变 Ctrl+C 的当前取消目标。普通 Composer 持续挂载，返回保留草稿/光标；新审批提示返回处理。

## 分批实施

1. 当前会话目录、分页、任务选择/完整目标与状态、准确历史检查；公开 App/BackendClient/stdio 测试及真实进程证据。
2. 选中任务接入、停止与后台审批：后端动作可用性只是展示快照，执行前重新复核；接入带完整 workspace/session/task 身份，实时连接与离线检查区分。替换原固定 sleep 重启，明确运行中处置、退出/失败恢复和草稿交接。审批复用现有 attach 通道，不能由列表直接猜批准。
3. 旧会话目录/预览/显式打开或续做：用途隔离、无自动运行、待办/草稿归属与切换失败恢复。空会话、坏记录、移动/删除、分页更新分别验收。

这三个批次都属于 P8 的完整要求；本批不将后两项改成可选。

## 验证与评审

先保存 640 文件基线；修改行为先加公开边界测试。重点覆盖审批中只读、分页/坏记录/错误范围、迟到回执、没有任务、中文/长目标/32×12、记录只读与零隐藏运行。每批冻结源码，完整回归、实际 Ink/Python 进程核验和范围差异归档。Ghostty 真人与 Owner Review 单列，不能从 fake/PTY 推断通过。

## 第一批协议与选择约定

- ready 声明 `task-navigation`；`tasks` 携带 `args: {}` 或 cursor 返回 `task_catalog`，不带 args 保留原文本 `command_result`。客户端必须保留空对象，不能悄悄丢弃参数。
- 固定每页 5 条，cursor 绑定规范工作区和会话；错误范围的 metadata 跳过并计数。无 worker、worker 损坏、异机 worker 分别表示，异机不猜本机 PID/心跳存活。审批日志不完整时数量未知并提示问题。
- 选择按任务 ID 保存；刷新当前页保留所选身份和阅读位置，移出本页后禁止沿用旧序号查看记录，须重新选择。查询有独立请求身份、超时和迟到回执隔离，不占执行队列。
- 查看记录的请求、回执都绑定 task_id，历史翻页沿用过滤条件，普通全会话入口清除过滤。主 Composer 持续挂载，草稿和光标保留。
- Python 与 TypeScript 均按 Unicode 码点验证长度：完整目标上限 4000，问题说明上限 500；不以 JavaScript UTF-16 长度误拒绝 emoji。
- 目录展示的事实不是接入、停止或审批授权；这些动作需要后续批次的权威状态和执行前复核。

## 第二批接入与停止

- 目录增加可选 controls，区分本机在线、可离线读取、不可用及原因；旧目录不猜操作。实际控制继续经过 worker 的控制权租约和已有审批通道，不新增跨任务批准协议。
- BackendClient 创建独立 attach 后端，确认 ready 的工作区/会话与 task_snapshot 的任务身份后才交给 App；10 秒超时、错误或取消只回收候选连接，原后端保持。父客户端退出也清理接入子进程。完整 task_snapshot 回放给稍后订阅的 App。
- 当前 App 保持挂载但停用输入，已确认的接入 App 接管屏幕；原会话暂停待办自动发送。任务草稿按工作区/会话/任务保存文字和字素光标，仅在当前窗口内存保留。返回只断开 worker，原输入框未卸载。
- 有当前运行时先选择等待或停止当前；暂停目标续段与后续消息，收到终态后才连接。接入等待中 Esc/返回取消候选，迟到连接立即回收。失败原因保留完整可滚动说明，未取得控制权不自动抢占。
- 停止动作重新取得控制连接，根据最新运行段 ID 只发一次 cancel。过期目录、离线或已结束不发送；后端还会验证取消目标。ack 不是终态，任务暂停/段取消才是实际收尾事实。
- 真实 PTY 暴露两项并修复：32×12 非审批状态的输入留白挤掉状态行；重开时把活跃 worker 的未完成工具补成崩溃结果。现保留状态行，活动/异机/损坏 worker 下跳过持久工具修复，确认退出的 worker 保持原修复行为；worker 自己启动的恢复路径不改。
- 返回后新模型调用的上下文刷新和同会话并发写入边界仍需单列核验，不能由输入框保留推断完成；它与旧会话切换一同作为 P8 收束门槛。

## 返回后的会话上下文与执行归属

第二批留下的上下文问题已通过 stdio 双连接复现：后台结果已保存，原 Agent 下一请求仍使用旧内存历史。现开始运行前接入最近有效的压缩快照、后续消息和 TaskState；保留 TaskState 对象的工具绑定。只在历史/状态实际变化时恢复，模式事件不能误触发重开文件保护。

同会话普通运行、显式续做、计划批准执行及反馈修订共用进程锁，从任务准备前持有至保存/收尾完成。锁由操作系统在正常退出或崩溃时释放；不删除锁文件，不依据旧心跳抢锁。启动工具修复与任务恢复也使用此锁，忙时只读打开，不把正在审批的工具补成中断。无进程锁的平台拒绝执行；工具动作仍走 ApprovalGate。

目录、历史和审批处理维持既有通道。`session_busy` / `session_unavailable` 明确表示本次未启动，普通输入恢复，界面回到空闲；持久后续消息按准确请求身份退回队列并暂停。未知传输错误仍保留待核对，不能重发。此锁约束当前 stdio 执行者，不是跨主机分布式锁或对外部脚本写会话文件的防护。
