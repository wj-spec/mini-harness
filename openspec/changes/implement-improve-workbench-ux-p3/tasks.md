## 验收矩阵

| 编号 | 输入/故障 | 必须观察的权威结果 |
|---|---|---|
| R01 | 先显示 A，再产生不同计划 B | 只批准/执行 Ref 指定的 A，B 状态不变 |
| R02 | 同族 v2 新建或同版本内容被改 | 旧 Ref 得到 superseded/content_changed，工具与任务启动次数均为 0 |
| R03 | 提案 TTL 过期、stale、tasks disabled、busy | 有结构化 code；拒绝前无批准/创建副作用；UI 保留草稿 |
| R04 | approve-only 与 dismiss | 前者仅批准；后者保持计划状态；均不调用 Provider、不创建运行段 |
| R05 | 重复确认、不同 request id、重连重试、两个进程竞争 | 同 Ref 的初始执行只有一个绑定任务和一个启动段；不同响应都指向它 |
| R06 | 批准已写，创建任务前失败 | 展示已批准未启动；显式继续复用预留身份、批准时间不被刷新 |
| R07 | task meta 写入后、operation receipt 更新前退出 | 查回同一 creation key/task_id，不创建第二任务 |
| R08 | starting 写入后、prepare_run 的 running/segment 写入前后退出 | 按持久证据和存活状态区分可继续/待核对；超时不能当死亡 |
| R09 | run 已登记、响应丢失或进程退出 | 查询返回原 run；重复 approve-execute 不追加 segment、不重放工具；原任务可按已有路径显式续做 |
| R10 | 操作/任务文件损坏、task key 不匹配、路径/symlink 不合法 | 拒绝覆盖与随机另建，解释需核对；原证据保留 |
| R11 | 查询发生在其他 run 活跃时 | active_id/取消目标不变；新启动被 busy 拒绝，旧操作结果可查 |
| R12 | 非当前请求的旧回执/重放事件 | 只更新对应卡片；不清当前输入、不切到别的 run、不自动执行 |
| R13 | 写草稿时到达卡片，输入 a/d，工具审批打断审阅 | 裸键不批准；工具审批优先；恢复后重新选择才可执行；草稿保留 |
| R14 | 32×12、80×24、120×40 + 长标题/正文 | 动作/确认/返回可见或进入小屏安全状态；全文分页完整且不混版本，复制/滚动不跳 |
| R15 | 一个已批准计划的工具写入被拒绝 | Gate 被调用，文件哈希不变，计划批准没有成为工具授权 |
| R16 | 旧产物（含缺 created_at）/旧命令、旧后端无 capability | 同文件反复查询/批准后 hash 稳定，查询不落盘；兼容可解释；新卡不退回文本猜测/盲串命令；有旧执行证据不自动另起 |

断言优先检查真实 Plan 文件、TaskRecord/segment、创建凭据、FakeProvider 调用数、审批请求和 workspace 哈希；不以某个内部 helper 是否调用替代行为验证。
故障注入点只服务真实 I/O/启动交接失败，不为镜像 Implementation 写测试。
