## 需求与目标态

### 痛点与受众

面向首次试用开源项目的人，以及日常在 Ink 工作台中完成编码任务的人。当前重点仍是可靠、可理解的单 Agent 编码流程。

用户明确反馈：每一轮 Agent 处理完都会出现一部分“本轮回执”，连续对话时形成重复干扰。此前讨论还涉及配置项过多、功能入口不易发现、启动和 LLM 配置门槛，以及 README 混入过多工程指标。

本方案把这些问题连成一条使用路径：看懂项目 → 启动 → 配置模型 → 发出任务 → 审批操作 → 看懂结果 → 找到下一步。现有 Logo、README 和启动工作的成果作为基础保留，新增开发集中在回执、配置分层和功能指引。

### 目标态与验收门槛

| 用户目标 | 可验证的结果 | 验证入口 |
| --- | --- | --- |
| 对话连续 | 普通问答、成功只读任务不自动追加独立回执卡 | 阶段 1 场景矩阵 |
| 重要结果可见 | 修改、失败、未验证、停止仍有清楚的结果与证据入口 | 阶段 1 场景矩阵 |
| 最小配置可启动 | Demo 不需要 Key；默认模型只填写 Key；自定义服务提供地址与模型名 | 阶段 2 新用户旅程 |
| 配置确实有效 | 示例中的每个配置可追溯到解析、消费、默认值、作用域与生效时间 | 阶段 2 配置契约清单 |
| 知道功能在哪里 | 初次任务能发现输入、审批、结果详情和帮助入口，无强制教程 | 阶段 3 实测后细化 |
| 启动后可调整 | 设置能说明当前值来源、修改范围、生效时间；运行中的任务不被意外改配置 | 阶段 4、5 细化后验收 |

不凭空设置满意度、转化率或“减少 80% 噪声”等数字指标。近期以确定场景、事件计数、自动化断言和真实终端体验验收；体验结论由用户实际使用确认。

### 范围与非目标

方案初稿只编写规划文档；用户批准后已启动阶段 1。整体实施覆盖上述路径，按独立成果分期交付，不把所有内容塞入一次改动。

- 暂不引入 Web/桌面第二套界面；Ink 足以支撑本次目标。出现终端无法承载的明确核心任务时再讨论。
- 暂不扩展多 Agent、长期记忆或云端账号系统；当单 Agent 的使用反馈证明需要时，回到长期路线图评估。
- 暂不建设遥测平台；现有测试、回放、PTY 和人工体验可验证本次行为。需要跨用户量化研究时再提出独立方案。
- 不重做既有权限系统，不降低 ApprovalGate、完成守卫或审计保护；复用现有机制，补上易懂的呈现和配置入口。
- 近期不承诺跨平台安装发布。现有启动工作尚未验证的 Linux、真实 API 与无 uv 全新安装仍作为已知验证缺口保留。

## 2. 目标结构与职责

~~~text
运行事实、变更账本、验证与计划验收
              ↓
       结构化结果快照
              ↓
       展示决策与中文文案
       ↙       ↓       ↘
  对话摘要   状态区域   详情/历史

启动配置 + 环境变量 + 用户设置
              ↓
     来源解析与作用域校验
              ↓
       新任务配置快照
~~~

继续使用 Python 后端与 React/Ink。core/ 保持纯标准库和既有分域，只描述运行事实与判定；app/ 负责模型、配置、持久化与协议适配；tui/ 负责展示和交互。不把中文文案或界面折叠逻辑下沉到核心。

结果采用可版本化的结构字段，复用现有 session/task/run/segment 身份，不新建第二套事件数据库。字段形状在阶段 1 spec 中确定，至少区分：执行终态、观察到的效果、验证状态、计划验收状态、停止原因、证据引用和待处理动作。展示结论是这些事实的派生结果。

## 3. 设计决策

### 决策 1：按实际结果决定回执层级

选择“默认安静、重要结果就近呈现、完整证据可展开”。不继续每轮固定生成同权重卡片，也不简单删除所有回执。前者会持续打扰，后者使用户丢失修改和失败信息。

以下规则从高到低应用；错误、风险和待处理事项不能被“没有文件变化”覆盖：

| 场景 | 默认展示 | 详情与下一步 |
| --- | --- | --- |
| 等待审批或输入 | 继续显示当前待办，不显示终态回执 | 现有审批/输入入口 |
| 失败、中断、取消、预算停止 | 简短原因及已保留的影响；不声称需求完成 | 证据、查看变更、适用的恢复动作 |
| 有失败验证、审计异常或无法确认的执行效果 | 简短提醒 | 失败项、证据及可执行建议 |
| 修改了文件，验证通过且覆盖最后修改 | 回复下方紧凑结果条，如“修改 3 个文件 · 检查通过” | 查看变更 / 验证详情 |
| 修改了文件，未验证或验证已过期 | 紧凑提醒，如“修改 3 个文件 · 尚未验证” | 查看变更 / 可用的检查入口 |
| 无文件变化，但执行了有外部效果的命令/工具 | 显示操作结果或“影响待核对” | 工具证据；不自动归类成只读成功 |
| 普通问答、成功且无异常的只读任务 | 只保留回答 | 保留可发现的证据入口，不追加独立卡片 |

“验证通过”仅说明指定检查的结果及覆盖范围，不能直接改称“需求已完成”。运行结束、命令成功、环境验证、计划验收和用户认可各自保留。

判断依据优先使用工具元数据、账本与审计。任意 shell 命令不因文件 diff 为空便认定无副作用；证据不足时保守显示“影响待核对”。不靠 classify_task 的问答/行动分类决定是否隐藏异常。

代价是需要梳理协议与多个展示消费者；收益是减少重复、避免错误的成功感。优先保证重要信息完整，其次减少常规干扰。回滚可以恢复展示策略，不删除历史证据。

### 决策 2：共享结构化事实，按任务边界收束

停止用自然语言正则作为新结果的状态来源。回答正文可以自由表达，紧凑摘要、状态区和检视区消费同一份结构事实及一致的判定规则。

同一任务的自动续段只更新进度；在任务最终结束或需要用户介入时呈现结果。内部 run/segment 仍逐段保存完整证据。新用户消息形成的新任务不与上一任务混并。

聚合结果必须保留前段修改、失败与后续修复关系：新的成功只有明确覆盖相关变更/检查时才能消除旧警告。回放、重连、前后台接入使用既有身份去重；不能按文案相同或“最后一条结果”误合并。

旧记录缺少结构字段时提供折叠的原始运行记录；不从“已验证”等字串推断新的强结论。历史中隐藏的证据依然可检索、可展开。迁移采用新增字段和兼容读取，具体协议版本与能力协商在实施 spec 锁定。

三镜比较：系统层面，结构化方案增加协议迁移成本，文本过滤短期更小但保留多源判定；用户层面，前者减少重复和误导，后者只能减轻表面噪声；开发循环层面，共享事实与展示函数需要初期回归投入，但减少以后逐处修改文案和正则的成本。优先事实一致，其次低干扰，再控制实现复杂度。

代价是需要覆盖实时、历史和 attach 三类路径。替代方案“只改标题/过滤字符串”成本低，但仍会出现多个区域结论不一致，不能解决根因。

### 决策 3：配置先确保真实，再减少首次暴露

默认 .env.example 只保留初次连接模型需要的项目：Key、服务地址、模型名，以及有明确说明的可选代理开关。默认服务只需填写 Key；Demo 不需要这些配置。使用向导不要求用户先理解模板。

其余配置转为有目录、默认值和适用场景的高级指南；测试/评测项进入开发文档，不再堆在新手入口。

| 配置类别 | 默认入口 | 启动后配置目标 | 生效原则 |
| --- | --- | --- | --- |
| Key、地址、模型、代理 | 启动向导 / 最小模板 | 设置 → 模型 | 空闲时验证并保存，下一任务采用 |
| 自主权限、审批规则 | 安全默认值 | 设置 → 权限，复用 /autonomy 与 /permissions | 沿用既有即时策略/撤销语义，不能用快照绕过撤销 |
| 步数、时间、token、费用、goal 上限 | 默认值 + 高级指南 | 设置 → 任务限制 | 创建任务时快照；旧任务保留原限制 |
| 上下文窗口、输出上限 | 经过验证的模型能力/高级配置 | 模型高级设置 | 不把 1M 作为所有模型的事实；未知能力清楚标注 |
| MCP 服务 | 专门配置文件与指南 | 设置 → 外部工具 | 空闲时重建连接，失败不替换可用配置 |
| 沙箱及网络范围 | 高级配置 | 高级设置 | 下一任务或明确要求重启；不得暗中放宽运行中权限 |
| 完成守卫、环境审计、契约反查 | 默认开启 | 高级说明；必要时受控修改 | 不作为新手推荐关闭项 |
| LLM 审计、通知、验收重试/超时、日志上限 | 高级指南 | 后续高级设置 | 说明额外调用、网络发送或资源成本 |
| fake 故障注入、时间偏移、benchmark 版本、调试路径 | 开发/测试文档 | 不进入普通设置页 | 仅测试/诊断用途 |
| 实验性委派、无人值守放宽 | 高级实验说明 | 后续另评估入口 | 不混进默认新用户流程 |

逐项盘点“声明 → 解析 → 消费 → 测试 → 文档”。对 VIBE_LLM_MAX_OUTPUT_TOKENS，近期推荐移除无效用户入口并记录未支持；真正接入请求上限时再恢复说明，避免为了精简模板顺手扩张模型协议。

替代方案“把所有环境变量搬进设置页”会放大无效选项和认知负担。先核实契约、再按场景提供设置，用户更容易知道哪些值得改。

### 决策 4：统一设置来源，明确生效边界

不增加一份与现有权限/MCP/profile 存储互相覆盖的平行配置。阶段 4 已盘点并选择复用安装目录 .env；共享读写在 app/runtime/model_config.py，不新增用户/工作区平行设置。

普通非安全配置的推荐优先级：显式 CLI → 进程环境 → 本次明确选择 → 已保存的工作区/用户设置 → 安装目录 .env → 默认值；阶段 4 实际采用 CLI → 进程环境 → 本次明确应用 → 安装目录 .env → 默认值；未引入工作区/用户配置层。设置页显示最终来源，被 CLI/环境遮蔽时明确提示，不能保存后假装已经生效。安全权限仍遵守 ApprovalGate 及其收紧、撤销、profile 约束，不能用通用优先级绕过。

既有 start.sh 自动读取安装目录 .env；高级 run_ink.sh / run_vibe.sh 当前使用进程环境。阶段 2 保持该行为并说明；阶段 4 若统一入口，必须单列兼容与迁移测试，不能静默改变脚本/CI。

Key 隐藏输入、脱敏展示，不进入事件、回执、配置快照或导出；快照仅保留必要的非敏感模型参数与凭据引用。保存通过 ApprovalGate、采用原子写入；失败保留当前生效配置和未保存编辑。连接检测由用户显式触发，提示可能发起模型服务请求，检测失败与保存行为分开说明。

运行中允许查看、编辑草稿，不替换当前模型客户端/工具集合。阶段 4 支持普通 OpenAI 兼容连接空闲应用；Demo、自定义 provider、额外审计客户端明确要求重启，后台 worker 保持原配置。重开旧任务保留其快照；缺失模型或凭据时要求选择恢复方案，不偷偷使用新的默认值。权限撤销依现有策略即时生效。

系统上采用任务快照比热切换更易隔离状态；用户需要理解生效边界，但能预测任务使用哪份设置；开发上复用存储、统一解析比复制配置源更易验证。优先运行可靠与来源透明，详细迁移取舍在阶段 4 spec 锁定。

代价是需要让配置页说明“已保存”和“已生效”的区别；它比热切换所有运行资源更可理解、容易测试。

### 决策 5：指引跟随任务场景出现

采用一次可关闭的初次提示、区域说明和就近提示，不加入强制多步教程或抢焦点弹窗。

五个区域按用户意图解释：

| 区域 | 用户要做的事 | 指引内容 |
| --- | --- | --- |
| 对话 | 描述需求、补充或纠正任务 | 输入、发送、运行中补充 |
| 计划/进度 | 看 Agent 准备做什么、正在做什么 | 审阅计划、当前步骤、继续/停止 |
| 检视 | 核对做了什么 | 变更、验证、工具证据 |
| 任务/会话 | 找回之前的工作 | 切换、恢复、查看后台任务 |
| 设置/帮助 | 调整使用方式 | 模型、权限、任务限制、命令帮助 |

首次入口可提供“了解项目 / 修改代码 / 审查变更”。选择后仅填入草稿，由用户审阅发送；已有草稿不覆盖。指引关闭后能从帮助重开，普通使用不反复出现。

每条情境提示只表达“当前情况、对你的影响、一个下一步”。例如模型未配置引导打开模型设置；等待审批解释此次操作；检查失败指向失败详情。未实现的设置入口不伪装成可点击功能。

复用现有键盘导航与帮助注册，先盘点快捷键冲突再确定按键，不提前承诺新快捷键。窄终端、滚动阅读、历史回放时不抢焦点或强制跳到底部。熟练用户可关闭引导。

替代方案“首页列满命令”一次暴露过多信息；“只做首次教程”无法帮助用户处理后续具体情境。因此选择轻量首用入口与持续的就近提示。

## 4. 验证、风险与实施边界

阶段 1 的测试矩阵至少包含：问答、只读成功、修改后通过、未验证、验证后再次修改、检查失败、无改动但有命令效果、工具拒绝、错误/取消/预算终止、等待审批、自动续段、历史重放、前后台接入、不同任务并发呈现。工具拒绝若使请求无法完成，必须有可见说明，即使 Agent 后续生成了正常文本。

先补行为测试再改实现。按影响范围运行 Python/Ink 测试；提交前运行 ./run_tests.sh，并用 ./run_ink.sh --fake 和实际 Ink/Python PTY 验证；涉及模型请求和配置时增加显式授权的真实 API smoke，未运行应写明。最终交付包含真实终端人工体验结果，不用测试数量代替体验结论。

重要风险：
- 隐藏过度：以异常优先和保守的未知效果处理兜底。
- 多处结论漂移：结构化快照与消费者一致性测试。
- 旧记录误判：只展示原始证据，不补造成功结论。
- 续段遗漏前次影响：任务聚合需保留证据来源与覆盖关系。
- 配置保存看似成功但未生效：显示来源、遮蔽原因和生效时间。
- 指引造成干扰：不抢焦点、可关闭、可重开、不覆盖草稿。
