| 样本 | 已核对的事实 | 原型可操作路径 |
|---|---|---|
| `recall-guard`，20261023-113622 | 18 次请求、23 个工具；Agent done，但独立 check 退出 1 | 失败检查 → 原始回执 → 请求占用/工具参数与结果 → 证据引用 |
| P3 会话 20261108-194449-131809 | 规划 8,518 + 执行 22,520 = 31,038 tokens；8 次请求、9 个工具；执行因预算暂停 | 分段状态与消耗 → 重开核验 → 重复读取与工具输出 → 任务身份缺口 |
| `execution-chain`，20261025-143841 | 同批 3 次通过，tokens 194,808 / 443,496 / 725,198 | 三次分布 → 第 3 次的 36 份请求前快照/41 个工具 → 定位上下文峰值 → 验证草案 |

工具记录中的“同参数重复”仅为排查入口；例如规划与执行分别读取同一文件，不能直接判作浪费。第 3 组使用请求前快照而非逐次 LLM 完成事件，逐请求实际 usage 与耗时均显示未知。上下文估算峰值在第 17 次请求，合计 23,197 tokens，不等于已确认的性能根因。

每个案例分别展示事实、假设、缺口和验证建议。可以引用具体检查、请求或工具，编辑拟改层次与最小验证，生成带来源摘要的改进草案；无证据时生成按钮禁用。草案只在内存，不修改代码、不触发模型/runner，也不形成基线采用决定。

**发现的采集缺口**：历史 Task segment 与 trace 的 run_id 表示不同；快照只有上下文来源、指纹与估算，没有完整请求正文；部分旧报告只提供模型别名/提交号或缺少配置；定价缺失。均作为 P1 输入，不由界面猜测补全。既有 `held_out` 案例在用于本轮诊断后，不能仅凭旧标签继续宣称未参与开发分析。

**工程核验**：浏览器走通三个样本、检查/来源展开、请求选择、峰值定位、重复动作筛选、证据引用及可编辑草案生成、无证据禁用、两版页面往返；采集到的浏览器 error 日志为空。截图 `.vibe/lab-prototype/diagnosis-preview.jpg`。新版页面按当前窄屏实际查看，无额外尺寸覆盖声明。

本轮未修改生产逻辑，未运行产品全量测试或真实模型。用户是否能据此独立解释失败、排除错误归因并选择下一步实验，仍待新版反馈。

## v0.1 原始记录

## 要回答的问题

修改 Agent 后，用户能否从两个实验确认可比条件、发现具体退步、查看相关证据，并指出下一步调查方向或识别证据不足？

原型使用“实验记录 → 版本对比 → 任务证据”三个视图。采用 `prototype` 技能的逻辑验证分支：单文件 HTML、内存状态、纯比较函数与页面分离，配套五条可重置演练。原型位于 `.vibe/lab-prototype/index.html`，按项目规则保留为不提交的本地产物；没有创建或提交临时分支。

## 数据来源与解释边界

六份模拟实验覆盖 SWE 对照、缺失证据、协议变化以及 Terminal 重复试次。模拟任务 ID 使用 `demo/`，Terminal 使用“演示 vA”，不代表实际主版本已选定。模拟分数不代表项目能力，也不是官方榜单结果。

两份真实历史记录来自：

- `.vibe/benchmarks/swebench-lite-dev/model/20261021-170835-513176/report.json`：预定 1 题、resolved 0；官方报告记录 empty_patch 1、completed 0，Agent 因 token_budget 停止。
- `.vibe/benchmarks/swebench-lite-dev/model/20261021-224536-308814/report.json`：预定 1 题、resolved 1；保留官方报告与实际补丁节选。

两个目录均嵌入运行报告、官方评分报告、原始补丁预览、轨迹边界摘要与 grader 日志，并保存这 10 个原文件的导入时 SHA-256。原型不嵌入完整消息或完整工具参数。通过例的原始补丁包含二进制块，预览明确省略该块；摘要覆盖完整原文件。

这两次运行同时改变 token 上限（100000 → 1000000）、step 上限（50 → 0）与本地协议（v1 → v2），所以只并排展示结果，不认定 Agent 改善。模型只有别名；完整起始运行身份和补丁转换链不足。目标仓库 base_commit 与报告 repository_head 不同，复现前仍需核查其来源，不能将该 HEAD 误作 Agent 版本。

历史价格配置为 0，不足以证明免费，费用显示“未知”。缺失试次的 token、耗时和费用也显示“未知”，并使完整总量未知。存在的空补丁与未收到的补丁分别呈现。

## 本次交互核验

在本机浏览器通过只监听 `127.0.0.1` 的临时静态预览核验；页面本身无后端依赖，禁止联网、无写入和运行入口。

| 路径 | 观察到的结果 |
|---|---|
| SWE 对照 → 比较 → 退步 → 证据 | 模拟总分 40% → 60%，仍可找到 1 个退步；补丁、时间线和独立日志关联同一任务 |
| 官方评分与 Harbor 冲突 | Harbor 1 / 官方 0，明确标记 score_disagreement，以官方失败为准 |
| 证据缺失 → 比较 | 有效样本 3/3，但预定分母保留 5；有效配对 3/5，总体分差“暂不计算” |
| 缺失任务 → 证据 | 缺失产物、未知消耗、没有事件分别表达；不伪造空补丁或零费用 |
| 版本冲突 → 比较 | 列明数据 revision 与评分器差异；不显示“改善”归因或总体分差 |
| Terminal 对照 → 试次证据 | 3 题 × 2 次共 6 条结果，逐次保留 reward；详情显示终端产物 |
| 真实历史 → 比较 → 来源 | 列明真实预算与协议变化；官方 resolved 1 可追到嵌入的原始 JSON |
| 真实历史 → 基线补丁 | 明确显示原文件为空、0 bytes，与缺失产物不同 |
| 搜索空态 / 清除筛选 | 无匹配提示与恢复列表可用 |
| 自由选择同一实验 / 跨基准与来源 | 阻止受控比较，显示具体原因 |

内联脚本 `node --check` 通过；10 个嵌入摘要与本地原文件核对一致；浏览器采集到的 error 日志为空。截图保存在 `.vibe/lab-prototype/preview.jpg`。

本轮没有修改生产行为、运行 `./run_tests.sh`、调用真实模型、启动 Docker、重跑 benchmark 或提交榜单。未做移动端、性能或生产集成验收。其他工作树改动未纳入本轮。

## 对后续实现的输入

1. **身份完整性先于分差**：一个源码 hash 不足以代表完整 Agent 运行版本；P1 仍需固定有效源码、指令、配置、模型、dirty 状态及快照可重建程度。
2. **逐试次与产物链是必要数据**：保留预定清单、attempt、空/缺预测、原始/送评补丁及转换身份，才能解释分母与评分冲突。
3. **未知必须传递到汇总**：缺失费用不能按 0，缺失评分不能通过删题提高通过率。
4. **原生协议保留差异**：SWE 的补丁与官方 grader、Terminal 的终端产物与 verifier 可共用导航，详情和聚合仍需服从各自协议。

这些是由原型与历史数据得到的实施输入，尚未转化为已验收的生产 schema。

用户体验仍需判断：能否不借助解释找到退步；“原生分母 / 有效配对 / 不可归因”是否清楚；证据是否足以决定下一步修改。反馈后收敛交互与字段，再进入 P1 实施规格；P5 的正式 Web 建设继续遵循原路线图依赖。
