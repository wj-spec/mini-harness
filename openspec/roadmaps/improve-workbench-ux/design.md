> 版本：v1，2026-11-08。状态：P1–P5 按阶段实施中，P6–P10 待实施；本文件保留整体目标与决策，已交付范围及验收证据以 [执行记录](task-log.md) 为准。
>

## 需求与目标态

### 痛点与依据

服务于个人日常编码与 Agent 原理学习，沿用 [建设方向](../../../docs/roadmap.md)；交付事实以
[MILESTONES](../../../docs/MILESTONES.md) 为准。W1–W5 的既有真实验收保留；较新的 Plan、TUI 键路和 Ghostty 体验按各自证据判断。

输入包括 [Ink UX 审计 U01–U11](../../../docs/research/ink-ux-audit-2026-11-08.md)、
[Plan UX 方案](../../../docs/specs/plan-ux.md)、[侧栏规格](../../../docs/specs/sidebar-git-panel.md)及本次侧栏代码核查。
前三者不是缺失功能清单：`/plan <任务>`、一次性 `/act <任务>`、滚动复制、侧栏和验收状态均已存在。

- 草稿字符可能成为审批动作；忙碌命令可能丢输入且无反馈。
- 通知和 Agent 更新可能打断阅读；侧栏 diff 的刷新依据不足。
- 计划审阅、修订、执行、验收和相关文件之间需要用户记命令串接。
- 队列、权限与任务恢复已有后端基础，界面尚未充分解释对象和动作。

### 目标态判据

1. 输入、审批、拒绝和停止都有明确焦点与反馈；任何授权都对应显式意图。
2. 阅读中的文件、位置与草稿不被后台更新夺走；更新可发现、可主动接入。
3. 用户可从计划审阅走到执行、验证、相关文件与后续修复；每个动作绑定正确对象。
4. 可发现已有命令、管理后续消息、找到等待处理的任务，并解释当前授权来源。
5. 框架选择由可复现体验与维护成本决定；迁移试验不阻塞明确的行为修复。

### 通用验收门槛

以下是全路线的质量要求，各阶段只验收其已交付能力；后期能力标记“待交付”，不能计为通过，也不阻塞近期阶段独立交付。

| 维度 | 门槛 |
|---|---|
| 用户控制 | 回归场景中误批准 0 次、草稿无提示丢失 0 次、重复启动执行 0 次 |
| 阅读稳定 | 指定场景中复制、刷新、Agent 新事件后，固定的文件和阅读锚点不变；文件删除给出替代状态 |
| 对象正确 | 旧卡片、两个同工作区会话、过期审批不能操作最新或其他对象；无法确认对象时显示不可操作原因 |
| 终端 | 主区 80×24、120×40；32×12 检查紧凑审批；侧栏 40/44/60 列；深浅主题、中文和宽字符 |
| 可用性 | 按 §4 的阶段映射完成适用真人场景，记录误触、查帮助、找不到入口和操作数；完整旅程累计验收，不以静态截图代替真人验收 |
| 工程 | 行为先补/改测试；相关 TUI/跨层回归；提交前 `./run_tests.sh -q` 与 `npm --prefix tui test`；环境失败单列 |

布局数字是拟定测试条件，不是已测出的最佳尺寸。确实低于最小支持尺寸时，只保留调整窗口与安全退出；实现前需明确该下限。

### 本轮不做与重启条件

- **全量替换 Ink**：先完成决策 1 的试验；只有比较证据满足门槛才另立迁移计划。
- **Web 入口、插件市场、多 Agent 总览**：本轮围绕编码旅程；出现第二个高频工作流再按 W7 评估。
- **通用 UI/review 框架**：目前共享交互约定即可；出现实际复用与重复维护成本再提取。
- **本轮级精确 diff、Undo/checkpoint**：目前明确展示工作区范围；需要可靠隔离用户已有修改时，再设计基线快照与冲突语义。
- **全新任务调度器**：先复用 attach、后台任务和现有队列；现有权威接口确实无法支持目标动作时再补接口。

## 1. 架构与演进

```text
现状：
主 Ink ⇄ JSONL ⇄ Python 后端 / ApprovalGate / Plan / Evidence
  └─ workspace 信号 → 独立 Ink 侧栏 ← Git 工作区

目标：
主工作台（输入、审阅、任务、结果） ⇄ 后端权威请求与事件
  ⇅ 带实例/会话/轮次范围的本地消息（在 P6 补齐）
检查侧栏（变更 / 计划 / 验证；跟随 / 固定；窄栏 / 放大） ← Git
  └─ 附加上下文 → 主对话草稿 → 用户提交 → 后端

P1 输入控制 → P2 稳定阅读 → P3/P4 Plan 旅程
→ P5 入口收敛 → P6 交付检查 → P7–P10 按使用反馈补控制与定位
```

| 组件 | 当前基础 / 后续职责 |
|---|---|
| 输入与焦点 | `tui/src/app.tsx`、`composer.tsx`、`view-state.ts`：显式动作焦点、草稿与提交结果 |
| 主区阅读 | `workbench.tsx`、`use-transcript-scroll.ts`：阅读锚点、结果动作与后续搜索 |
| 独立检查侧栏 | `tui/src/sidebar/`：Git 读取、稳定 diff、视图状态、Ghostty 宿主适配 |
| 命令入口 | `protocol.ts`、`backend.ts`、Python `stdio.py`：描述、可用状态、参数与实际处理器对齐 |
| Plan | `app/runtime/plan*.py`：版本、审阅、修订上下文、绑定执行；TUI 只发意图 |
| 任务与证据 | `app/session/` 及现有 task/worker 接口：任务、round、验证事实与恢复 |

维持 `core/` 标准库与四域约束、`app/` 分域边界。运行数据和本规划的评审临时记录均写 `.vibe/`，不提交。

## 2. 决策

### 决策 1：保留 Ink 主线，侧栏承载可撤销的 OpenTUI 对照试验

| 候选 | 系统影响 | 用户影响 | 开发与学习成本 |
|---|---|---|---|
| 继续 Ink，修行为 | 最小协议变动、容易回退 | 最快消除已复现问题 | 继续维护部分编辑/渲染设施 |
| OpenTUI + React 局部试验 | 独立入口、可复用 Git/协议逻辑 | 可比较 diff、滚动、中文体验 | 要验证原生依赖、运行时和测试链 |
| 整体重写 / 同时改 Solid | 前后界面切换面大 | 修复交付延后，易引入新回归 | 同时学习框架与重做产品行为 |

**选择**：第一项交付产品修复；P2 通过后可启动第二项，有收益再决定侧栏替换，主界面迁移另行决定。
用户控制与及时交付优先，接受短期保留自定义 Ink 组件的维护成本。

试验最多投入 **2 个专注开发日**，这是建议的止损预算，不是工期承诺。固定依赖版本、相同机器/终端/数据；
比较 500 条消息回放、1,000 行 diff、连续刷新、缩放、选择复制及退出后的终端恢复。
侧栏不能证明 composer 合格：另做最小输入夹具，验证中文组合输入、多行粘贴与审批到达时的焦点。
记录输入到呈现的 p50/p95、内存、复现缺陷、需要保留的自定义代码和安装步骤；先测 Ink 基线，不预编性能收益。
只有关键场景零新增回归，且至少一项已确认的阅读/编辑问题有可重复改善，才提出替换；失败或超预算回到 Ink。

截至本次查阅，[OpenTUI 支持 React](https://opentui.com/docs/bindings/react/)；其
[运行时要求](https://opentui.com/docs/getting-started/runtime-support/)为 Bun ≥1.3.14，或 Node ≥26.4 + experimental FFI。
当前项目声明 Node ≥22，不能把迁移当成只替换 npm 包。实际试验时重新核对所锁版本。

### 决策 2：动作焦点与输入焦点显式分离

审批到达展示等待状态，但不把继续输入的字符解释为批准；显式进入动作区后选范围并 Enter 确认。
Esc 优先返回草稿，不隐含批准/拒绝；拒绝是具名动作，Ctrl+C 沿用停止语义。
阻塞动作的提示优先于 Plan/Goal 装饰性状态；扩授权不能靠未聚焦的裸字符触发。

命令提交需有可解释结果：已受理、未执行及原因、或结果未知。未受理保留草稿；前端发送成功不等于后端成功。
忙碌时先明确拒绝不支持的命令，不顺带引入后台命令并发或隐形排队。
P1 可增加小型可用状态描述，P5 再统一帮助/菜单，避免两次复制命令规则。
替代的“所有审批强抢焦点”虽简单，会重复 U01；提前做通用弹窗框架无必要。此处用户控制优先。

### 决策 3：阅读有跟随与固定两种状态

```text
跟随 ──用户滚动/选文件──→ 固定
固定 ──后台更新──→ 固定 + 未读提示
固定 ──显式恢复跟随──→ 最新有效事件对应的文件/位置
复制、轻反馈、主题变更：不转换阅读状态
```

主区和侧栏遵循同一语义，但不共享一个全局滚动状态。侧栏最新文件按事件顺序，而非累计路径数组第一项选择。
读取所选文件的内容变化不能只依赖增删行数；由内容修订指纹或显式失效信号驱动，且覆盖外部编辑。
固定时保留正在阅读的 diff 版本并显示新版本可用；用户接入后再更新，必要时标明原锚点已不存在。
对不存在文件、Git 错误、过大或二进制 diff 给出具名状态，不静默切到别的文件。

伴随侧栏默认显示文件列表与局部 diff；专注状态放大阅读并恢复原布局。
[Ghostty `toggle_split_zoom`](https://ghostty.org/docs/config/keybind/reference#toggle_split_zoom)可放大当前 split，
但应用内触发与定位目标 pane 仍需本机验证；不预设键位、不自动改用户配置。
P2 先让手动 Ghostty zoom/resize 不丢位置，P6 再做专注审阅入口和联动。

替代的“每次刷新直接替换内容”维护简单，却破坏阅读；全程关闭跟随又削弱陪伴反馈。
选择显式双状态，接受保存当前可见版本和未读提示的少量状态成本。

### 决策 4：Plan 审阅绑定版本，批准并执行是一项可恢复操作

P3 复用已存在的一次性 `/plan <任务>`。新卡片展示标题、摘要、完整正文与版本，动作必须显式聚焦。
“批准并执行”绑定 `plan_id/version/hash`；后端复核 stale/TTL、busy 与已有绑定。
双击、重复响应、超时后重试不可重复启动；批准成功而执行未启动时显示两阶段结果，并从同一对象显式恢复。
不沿用旧方案“无需新增协议”的承诺：实施设计先确认现有响应能否关联并去重，不足则补后端意图/响应。
计划批准不替代工具层 ApprovalGate。

P4 再实现“反馈 → 只读修订 run → 新版 proposed → 重新审阅”。携带原版本与反馈，旧批准不继承到新版；
修订失败/取消保留反馈与旧计划，不自动执行。这样 P3 可单独交付，P4 有稳定承载。
替代的前端盲串两条命令成本低，但结果未知时难恢复；提前引入通用事务/审阅平台成本过大。权威绑定和可恢复性优先。

### 决策 5：明确命令、模式与队列的语义

- P5 菜单高亮候选后 Enter 接受候选：需要参数则填入模板；完整无参命令才执行。无候选时按原输入提交。
- `/act <任务>` 仅覆盖该次 run；退出粘性 Plan 是独立可见动作。Esc 先关闭当前覆盖层，不借同一个键隐式更改粘性模式。
- 恢复会话显示模式和草稿提示，不自动启动任务；pending 只有能真实产生并确认生效时才展示。
- P7 的“后续消息”队列与后台 Plan `/queue` 分开命名和呈现。error、cancelled、结果未知、明确验收失败时暂停自动续发，保留待办供撤回/编辑/继续；正常完成且无失败判据时再按显示的策略推进。
- P9 权限面板区分有效档位、临时授权和持久策略；reset 文案准确表示撤销本进程授权，不能暗示全量恢复 ask。

这修正了 `plan-ux.md` 中“/act 清除粘性模式”与其 S5“只覆盖一次”的冲突，保留已实现的一次性覆盖约定。
方案把对象与行为展示清楚，接受旧命令兼容与新菜单暂时共存；不强迫用户一次记住新命令集合。

### 决策 6：侧栏扩展依赖带范围的数据，而非猜测最新任务

P6 建立最小范围标识：workspace、主进程实例、session、task/run/round（不存在时明确为空），以及单调修订号。
启动、信号路径、pane 复用和销毁必须指向同一实例；两个同工作区会话不可覆盖信号、附错草稿或关闭对方 pane。
旧版信号仅允许工作区只读视图，不能假装已绑定任务；普通状态更新不应清掉仍有效的计划摘要。

“变更 / 计划 / 验证”共享对象范围。文件筛选可叫“本轮触及”，diff 始终标明“工作区 vs HEAD”；
用户已有改动不会被宣称为 Agent 独有改动。验证来自后端结构化事实，不解析自然语言判成功。
“已读”绑定 diff 版本，更新后失效；与 verified、计划批准分别存放。
附到草稿带选定路径/变更块与来源版本，保留已有输入、回执确认、按 request id 去重；仅附草稿，不自动发送或执行。
主进程不存在、对象不符、上下文过期时显示失败并保留选中内容，允许显式复制为回退。
本地消息只接受已知类型、限定大小和路径范围；内容作为不可信引用，不能成为审批指令。

替代的 workspace 单文件信号最简单，可继续承载 P2 的只读刷新；跨任务结果导航与双向操作需要以上范围。
此处对象正确性优先于“所有视图总跟随最近一次事件”。

## 4. 失败路径、验证与回退

| 触发 | 用户可见结果与处理者 | 验证位置 |
|---|---|---|
| 审批到达/重复事件/过期 | 主区保留草稿；只允许有效请求一次应答；过期后拒绝提交 | P1 Ink 输入与 reducer；后端审批集成 |
| busy/closed/命令发送异常 | 未受理原因可见、草稿保留；授权徽标等待后端确认 | P1 命令状态矩阵 |
| Git 无仓库/空/读取失败/文件删除 | 侧栏展示不同状态；不把旧 diff 标为当前 | P2 Git、状态与渲染测试 |
| 内容变而行数不变/事件乱序 | 内容刷新可达；固定版本不被替换；只接入更新的有效版本 | P2 确定性状态测试 |
| 放大、缩小、host 操作失败 | 保留文件与锚点；宿主失败不影响主对话和后端 | P2 本机；P6 宿主适配 |
| 批准完成但启动回执丢失 | 展示结果未知，先查询绑定再恢复；不盲目重发执行 | P3 跨层故障注入 |
| 修订失败/取消/旧版本批准 | 保留原计划和反馈，等待显式下一步 | P4 fake 与真实 Plan 用例 |
| 信号陈旧/跨会话/主进程退出 | 提示未连接或只读；拒绝附错对象，不恢复自动执行 | P6 多实例、生命周期与消息测试 |
| 排队后失败/断线/退出 | 显示暂停或未发送项；显式处理草稿与待办，恢复不自动续发 | P7 断线/恢复场景 |

行为修复按小 change 回退，不移除安全门。试验独立入口保持默认 Ink 可运行；回滚界面不能重放未知副作用。
真实 provider 仅在涉及规划、修订或验收上下文时使用，沿用项目预算配置并记录实际用量；UI 回放/搜索/菜单本地完成，不新增模型调用。

真人场景按能力累计验收：

| 场景 | 首次完整验收阶段 | 前期如何判定 |
|---|---|---|

| 主区复制不跳动；侧栏更新、固定阅读、恢复跟随与缩放保持位置 | P2 | P2 必须完成，不等待双向草稿或验证页 |

| 从同一会话的旧结果进入失败验证和相关文件，复制、附到草稿再返回原位置 | P6 | P2 只验证阅读子场景，完整结果/草稿旅程待 P6；跨会话对象选择另归 P8 |

每项记录版本、终端、尺寸、模型配置、实际输入、结果、操作次数与未解决问题；没有做过的验收明确留空。
阶段验收通过不等于整条路线完成，最终收束时需要回查全部累计场景。
