## P9 · 授权解释与撤销

- [ ] 触发一次会申请授权的工具（如 `VIBE_FAKE_DEMO=plan ./run_ink.sh --fake --autonomy ask`），在审批中选择更大范围的授权（「更多授权」里的本会话/工作区档位），让进程内授权出现。
- [ ] 输入 `/permissions`：预期面板显示
  - 当前档位与来源（本进程 CLI / 用户策略默认 / 默认 ask；若有 project 上限则显示被收紧）；
  - 进程临时授权逐条（workspace / session 分开，含工具、目标摘要与「本进程内有效，退出后失效」）；
  - 持久策略规则（[user]/[project]、来源文件、说明进程内不可撤销的原因）；
  - 策略错误时显示「保留上一份策略」原因。
- [ ] 选择一条进程内授权点击「撤销所选」：预期提示「已撤销 …；剩余 N 条进程授权」，列表只剩其他授权；再触发同类工具调用时应重新审批（不是静默放行）。
- [ ] `/permissions reset`：确认 P1 文案与语义不变（撤销全部本进程授权，档位与持久策略不变）。
- [ ] 撤销后立即再发起一次同类工具调用，核对审批提示确实出现；记录撤销前后的行为差异。
- [ ] 可选：写坏 `<workspace>/.vibe/permissions.json` 后重开，确认面板显示策略加载错误且保留上一份策略；恢复文件后刷新面板。

- [ ] 持久规则撤销（需先在 `~/.vibe/permissions.json` 或 `VIBE_PERMISSIONS` 指定的用户策略文件里放一条规则，如 `{"tool":"bash","command_prefix":"pytest","decision":"allow"}`）：
  - [ ] `/permissions` 面板中该条目标注「可撤销」，project 文件里的规则标注「不可撤销（修改仓库文件）」；
  - [ ] 选中 user 规则点「撤销所选」：预期进入二次确认（此时不应写入文件）；再次确认后提示「已撤销持久规则 …；剩余 N 条用户策略」，用户策略文件已删除该条且保留 `autonomy`/其它规则；
  - [ ] 撤销后同类命令不再自动放行（重新审批），`Esc` 可取消确认。
- [ ] 项目规则不可在面板撤销；尝试未知规则 id 或删除策略文件后撤销应给出明确错误且不改文件。
