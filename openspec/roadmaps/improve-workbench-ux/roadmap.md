## 概览

推荐顺序：**输入控制 → 稳定阅读 → Plan 审阅/修订 → 入口收敛 → 结果检查 → 运行与历史管理**。
保持 Ink 默认入口；OpenTUI 用独立对照试验回答是否迁移，不阻塞行为修复。
阶段是可独立验证的交付物，不按“同一批发现的问题”混装。实施包为 [P1 输入与审批控制](../../changes/implement-improve-workbench-ux-p1/proposal.md) 与 [P2 稳定阅读](../../changes/implement-improve-workbench-ux-p2/proposal.md)，不初始化或迁移其他工程流程。

**初版只细化 P1、P2**，两者先改善日常输入与阅读；随后完成 P3 协议/失败恢复和 Ink 审阅卡，受控真实模型写入/验收与原会话离线重开通过。P3 核心演示已获真人确认；P2 真人、P3 原生重开/恢复与学习 Review 仍待反馈。当前已细化 P4 并接通同族修订、卡片反馈与重开恢复；回执丢失、同族新版竞争已有实际进程验证，真实模型和真人完整验收待做；P5 入口、模式恢复及紧凑布局通过工程验证，真人验收待完成；P6 实例隔离与基础运行/计划投影已接通，其余检查区继续实施；P7 控制与持久恢复通过工程验证，真人验收待做；P8 当前会话导航、接入/停止、会话上下文同步/执行互斥与旧会话预览/显式打开通过工程验证，真人与真实终端待做；P9 权限面板通过工程验证、真人待做；P10 保留目标与补细条件。
优先逐阶段交付验收。依据用户持续开发授权，本次先推进与 P2 原生体验反馈无技术依赖的 P3 后端查询；不把待反馈当作验收通过。接入审阅 UI 时已核对：P2 原生反馈仍待收到，本次保留主工作台阅读/复制语义，侧栏保持不动；各阶段仍分别满足其退出条件。
没有个人投入时间基线，因此不承诺日历日期；首个迭代以 P1/P2 的行为验收为边界。

## P1 · 输入与审批控制

**体验反馈增量**：用户认为快捷键审批体验很差，优先增加可点击按钮、更多授权和 Tab 导航。已完成代码、9 项新增 TUI 回归及三种尺寸实际 PTY；新按钮 Ghostty 体验待确认，见 [增量证据](../../changes/implement-improve-workbench-ux-p1/verification.md#审批按钮增量2026-11-08)。随后继续 P4 原范围。

### 前置条件

- [x] 对当前未提交的 Plan 工作形成可识别基线，保留已有修改；不将其混入 UX change。
- [x] 重跑 U01–U03 探针，将行为契约固化为正式回归，记录已存在的 PTY 环境失败。
- [x] 列清输入/审批/覆盖层焦点优先级与各命令 idle/running/stopping/waiting_approval/closed 状态结果。

### 目标

用户可以在审批到达时继续编辑，显式进入动作区后才决策；未受理命令保留输入并解释原因。
关键阻塞操作不被状态前缀挤出屏幕。（见 [design.md 决策 2](design.md#决策-2动作焦点与输入焦点显式分离)）

### 子任务

- [x] **一个完整 change：输入与阻塞动作的显式控制**（代码与核心交互已验收，扩展场景单列）。
  覆盖审批焦点/范围确认、紧凑提示优先级、命令受理反馈，以及与授权操作相关的 reset 准确文案。
  只改必要的焦点、提交结果与提示路径；不做完整命令面板或权限管理器。

### 验收标准

- [ ] 草稿中逐键输入 `y/s/p/n`、粘贴、按键重复与审批交错，未进入动作区时 approve 调用为 0；草稿不丢。
- [x] 聚焦后可完成允许/拒绝，过期、重复、送达失败有反馈；Ctrl+C 仍能停止（自动回归通过）。
- [x] 在 32×12、80×24、120×40 与 Plan/Goal/长标题组合中，审批选项及拒绝/停止可发现；不能容纳时进入明确的小屏安全状态（确定性渲染回归通过）。
- [x] `/autonomy edits` 等在各运行状态下都有已受理/未执行/未知的可解释结果，未受理保留草稿，徽标等待后端确认。
- [x] reset 显示撤销本进程授权，并提示仍有效的档位/策略；不改变 Gate 决策。
- [ ] 自动回归与 Ghostty 中文输入/审批交错人工检查分别记录；全量命令按项目要求执行，环境失败单列。

### 交付物

可用的输入与审批控制、对应回归和人工验收记录；同步受影响的使用说明与审计问题状态。
当前证据：[P1 实施、评审与验证](../../changes/implement-improve-workbench-ux-p1/verification.md)。自动回归与工具驱动 PTY 已通过；用户已确认 Ghostty 核心交互符合预期。原生缩放/候选框交错等扩展场景及 Owner 学习记录单列待补。

## P2 · 稳定阅读

### 前置条件

- [x] P1 已验收或明确记录未通过项；涉及同一输入键路的问题解决后再动主区阅读。
- [x] 固定主区回看与侧栏样本：中文长路径、A→B→A 修改、等行数内容更新、删除/重命名、空仓库和 Git 失败。
- [x] 明确固定 diff 的版本保留策略、缓存上限及刷新触发，按本机测量设定，不依赖行数签名。
- [x] 固定机器、仓库规模和编辑样本，先测 Ink 基线，再在实施设计锁定更新提示最大延迟、刷新期间输入响应 p95 与缓存字节上限三个数值；未填写不得开始刷新机制改动。

### 目标

复制/轻提示保持主区阅读锚点；侧栏用户一旦开始读，就固定文件与当前版本，后台更新可提示且可主动接入。
文件名、焦点和当前动作在窄栏可辨认，缩放不丢位置。（见 [design.md 决策 3](design.md#决策-3阅读有跟随与固定两种状态)）

### 子任务

- [ ] **一个完整 change：显式跟随与稳定阅读**。
  覆盖主区轻反馈、侧栏固定/恢复跟随、最新事件排序、内容更新检测、窄栏文件名/焦点/提示与缩放状态保持。
  P2 不引入侧栏双向写草稿、任务验证页或新的主界面布局。

### 验收标准

- [x] 主区向上回看后复制成功/失败、主题或轻通知不跳到末尾，失败提示仍可见。
- [x] 侧栏滚动或选文件后，Agent 新事件只增加更新提示；恢复跟随选中最近有效事件文件，A→B→A 顺序正确。
- [x] 同文件内容变化但增删行数不变时也能发现更新，外部编辑亦成立；固定状态不默默替换正在读的文本。
- [x] 在已固定样本下实测更新时效、输入响应和缓存占用，达到本阶段实施设计锁定的三个数值门槛；不能仅以最终刷新成功作为通过。
- [x] 删除/重命名/空结果/Git 错误/二进制或超大差异各有明确状态，不能把过期内容冒充最新。
- [x] 40/44/60 列下文件名和关键操作可读，完整路径可查看，列表/diff 焦点可辨；不能只靠颜色区分。
- [ ] 80×24、120×40 下用 Ghostty 原生缩放/zoom 后恢复阅读对象；开栏只做一次初始化校准，不持续覆盖手动比例。
- [x] 明确展示“本轮触及文件”与“工作区 vs HEAD”；单一主会话条件记录清楚，跨会话身份协议归 P6，观察到串台即提前处理该前置。
- [ ] 同一输入事件集重复回放结果一致；相关 TUI 回归、全量检查和本机体验记录齐备。

### 交付物

可稳定阅读的主区与侧栏、刷新/跟随回归、固定尺寸样本和真实终端验收记录。
实施包：[P2 稳定阅读](../../changes/implement-improve-workbench-ux-p2/proposal.md)；[自动验证与真人验收边界](../../changes/implement-improve-workbench-ux-p2/verification.md)。
P2 通过后可按 [design.md 决策 1](design.md#决策-1保留-ink-主线侧栏承载可撤销的-opentui-对照试验)启动 OpenTUI 试验；结论可为保留 Ink。
