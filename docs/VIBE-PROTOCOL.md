# Vibe 协作协议

> 你提出：手写每一行太慢，想用 vibe coding 提高效率。同意。
> 但 vibe coding 要有验收，否则会变成"能跑，但我讲不出"。
> 这份协议定义：谁写、谁验、什么算过。

---

## 1. 角色

| 角色 | 谁 | 负责 |
|---|---|---|
| Owner | 你 | 定 spec、改需求、决定取舍、在闸门口试 |
| Reviewer | 你 | 读 diff、跑测试、做 mutation、写 5 行笔记 |
| Implementer | 我 | 写 spec 草稿、实现、写测试、跑测试、补文档 |
| Explain | 你 | 每个切片 3 分钟脱稿，讲输入/输出/失败路径 |

**一句话**：我负责让它跑，你负责让它"讲得通"。

---

## 2. 每个切片的五步

1. **Spec（我起草，你改）**：一页，写行为、接口、失败路径、不做什么。
2. **Tests（我写，你审）**：先失败；你确认测试真的在测行为，不是测实现。
3. **Implement（我写）**：按测试写，不扩范围。
4. **Review（你做）**：读 diff，回答下面 5 个问题；跑一次 mutation。
5. **Note（你写）**：5 行，必须有证据 + 一个反例。

**没过 review，不进下一个切片。**

---

## 3. Review 的 5 个问题

每个切片，你都要能回答：

1. 这个模块的输入、输出、副作用是什么？
2. 哪一行是"唯一决定行为"的分支？
3. 哪个失败路径没有测试？
4. 如果删掉这段，哪个测试会红？
5. 这段代码在什么情况下会骗我（假成功 / 静默失败）？

答不出第 2 或第 4 条，就说明你还没看懂；我们把这部分重写一遍，而不是继续往下。

---

## 4. 规则

- **没有失败测试，不写实现。**
- **没有 review，不算完成。**
- **不扩范围**：一个切片只做一件事；想要更多，记进 `问题清单`，下一个切片做。
- **不静默失败**：错误要么回灌给模型，要么返回 `status="error"`，不用 `None` 糊过去。
- **AI 生成的代码要能指到测试**：每个公共函数至少一个测试。
- **讲不出就重写**：闸门时红区任何一行讲不出，不算过。

---

## 5. 你仍然要自己做的东西

- 改 spec：AI 写的 spec 一定有取舍，你要说"这个取舍我认不认"。
- 读 diff：不是扫一眼，是能指出"这行为什么在这儿"。
- Mutation：改一个条件，预测哪个测试红，再跑。
- 写笔记：5 行，不是抄代码。
- 口试：3 分钟，不看代码。

这五件事，才是你的学习发生的地方。代码谁敲，不重要。
