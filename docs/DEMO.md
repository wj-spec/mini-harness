# 3 分钟 demo

## 直接体验审批按钮（无需模型）

```bash
VIBE_TASK_RUNTIME=0 VIBE_FAKE_DEMO=1 ./run_ink.sh --fake --autonomy ask
```

等待顶部状态变为「就绪」，按 Enter 提交预填内容，即出现写入审批。点击「允许本次写入」后出现命令审批，点击「允许本次命令」完成。启动中的“后端就绪后可发送”仍是等待提示；若提前按 Enter 显示草稿保留，待就绪后再按一次。
也可点击「拒绝」或展开「更多授权」；审批期间输入中文草稿，核对点击后草稿与光标。仅写 `.vibe/fake-demo.txt`。
计划演示需要先批准计划执行才出现工具审批；只检查按钮时使用本节命令。

完成上述演示后，可测试重开结果：记下顶部会话 ID，Ctrl+Q 退出，将下面的 `SESSION_ID` 替换为该 ID：

```bash
VIBE_TASK_RUNTIME=0 VIBE_FAKE_DEMO= ./run_ink.sh --fake --autonomy ask --session SESSION_ID
```

等待就绪，点击“历史结果”→该运行的“验证”，侧栏应显示原命令和退出码；无需发送新任务。也可 `/inspections` 打开列表，Tab 选择记录、Enter 查看验证，←→ 翻页，Esc 返回。草稿和光标保留；历史列表不等于重新执行。自动多轮分页、准确修订 v2 与突然退出的证据见 [P6 历史入口验证](../openspec/changes/implement-improve-workbench-ux-p6/verification.md#重开历史结果入口2026-11-09)。

## 在主区专注检查

完成第一节审批演示后，输入中文草稿并移动光标，点击“专注检查”（窄屏“检查”）。切到“验证”核对实际命令与退出码；“变更”读取当前来源目录的 diff，拖选后可点击“附回”，不会自动提交。点击“返回草稿”或 Esc/q 回去继续输入，光标应保持。再次进入保留页码和选区；也可点击“独立侧栏”伴随查看。

检查期间若出现工具审批，会显示“待审批 · 返回处理”；返回主区再点击审批按钮。停止与退出仍用 Ctrl+C / Ctrl+Q，并控制当前任务。切换到 32×12 可核对紧凑入口与返回按钮。自动/实际 PTY 证据见 [专注检查记录](../openspec/changes/implement-improve-workbench-ux-p6/verification.md#内嵌专注检查2026-11-09)，真人体验单列待验收。

## 选择当前会话任务

使用下方「计划审阅与执行」演示生成一个任务，随后在主区输入中文草稿并移动光标，点击「任务」。核对完整目标、任务状态、优先级、更新时间与待审批数，再点击「查看记录」，应只出现这个任务的原运行。返回后继续输入，草稿与光标应保留。普通 fake 对话可能没有持久任务，空目录属于正常结果。

同一会话累积多个任务后，可点击「前条 / 后条」选择，超过 5 条用「更早 / 较新」翻页。「刷新」应保留当前页和任务选择；若原任务已不在本页，明确提示重新选择。缩到 32×12 核对按钮和返回入口。浏览目录不批准、不启动、不停止任务；新审批提示返回主区处理。自动与实际终端证据见 [P8 验证](../openspec/changes/implement-improve-workbench-ux-p8/verification.md)，Ghostty 真人体验仍待验收。

对已有本机后台 worker 的任务，点击「接入任务」，无需复制 ID 或重启；进入后可直接点击审批按钮。输入另一段中文草稿并移动光标，点击「返回原会话」，原草稿应保持；再次接入，任务草稿也应恢复。返回不会停止 worker。

worker 仍运行时，在原会话提交新需求，应提示会话已占用、保留输入，不会并行启动。可继续从「任务」进入原审批；等待 worker 结束或显式停止后，再提交需求，模型将使用该会话最新保存的历史、压缩快照与任务状态。被明确拒绝的持久后续消息回到队列，需点击「继续」才重试；关闭窗口重开不会自动发送。

另用一个允许中止的演示任务，点击「停止此任务」：应显示停止请求与收尾，最终进入离线只读。已保存结果的任务提供「离线查看」，不会重新执行。当前主会话正在运行时，接入先提供等待或停止当前后接入；取消连接、其他窗口占用控制权和 32×12 状态也可单独检查。审批只验按钮时仍使用文首的 `VIBE_FAKE_DEMO=1` 命令；普通前台演示不会自动生成后台 worker。

## 后台任务结束后查看结果

对已经运行过的任务，把下列占位符替换为原工作区、会话和任务 ID（fake 任务带 `--fake`，真实任务省略）：

```bash
./run_ink.sh --fake --workspace /原工作区绝对路径 --session SESSION_ID --attach-task TASK_ID
```

点击“历史结果”读取该任务的记录，再选择“计划”或“验证”。worker 仍连接时可以查看，worker 退出后会显示“离线只读”；无 socket 但存在记录时同样可重开。离线不会重新执行，提交普通文字会保留草稿，Ctrl+Q 退出查看。没有保存记录时会明确报错。原始任务仍以实际 TaskRecord 为准，断线不等于任务完成。

也可选择“变更”：新记录按保存的实际目录显示当前 diff，后台任务应显示“任务目录”。目录被清理或替换、旧记录未保存来源时明确不可读，计划/验证仍可查看；历史记录不等于历史 diff。文件路径详情和附回引用可核对来源目录。

可选：在上述计划演示中先输入 `/sidebar` 打开绑定侧栏，再输入 `/plan 写入 .vibe/plan-demo.txt 并校验内容` 提交需求。生成计划后，在侧栏点击顶部“计划”阅读完整目标、步骤、约束与审阅身份；执行结束后查看运行状态，未取得步骤结果时应显示“进度未知”。返回主区输入 `/cost`，计划摘要应保留；提交新的普通需求后，上轮计划和“本轮触及”标记清空。普通需求没有持久任务时显示“未绑定运行段”。

计划执行前点击“计划”打开阅读，执行结束后应提示“有更新”；点击顶部“接入”才更新执行快照。点击“验证”查看结果与实际命令 `exit=0`，滚轮 / ↑↓ 或 PgUp/PgDn 翻阅；切到“变更”再回来应保留位置。主区提交下一任务，验证页仍保留原记录并提示更新；点击“接入”后清空旧命令，显示新任务的未知验证状态。

计划正文可用滚轮 / ↑↓ 阅读，长计划点击“上页 / 下页”或用 ←→ 换页，点击“返回”回到变更。读取失败时原页保留，点击“重试”；32 列窗口仍能看到页码。演示计划较短，通常只有一页；900 条中文/emoji 约束的四页样本已通过实际后端与原生 PTY 核验，过程不调用模型。

可继续体验结果入口：在主区刚完成的结果下点击“计划”或“验证”，侧栏应显示“结果快照”。提交下一任务，旧结果继续保留；点击主区“回到当前”后，侧栏接入新任务，旧验证命令不会混入。点击前可输入中文草稿并移动光标，核对点击后保留。变更内容仍是当前工作区 diff，触及标记来自所选结果。

范围、固定阅读、当前进程内结果导航和恢复行为有实际终端脚本验证；Ghostty 原生开栏与真人阅读体验仍待验收。重开历史、attach 的计划/验证只读、diff 已读与计划跨页选区已有工程验证；worktree 文件来源/diff 路由已接通；内嵌专注检查仍待补齐。

## 计划反馈与修订（无需模型）

```bash
VIBE_TASK_RUNTIME=1 VIBE_FAKE_DEMO=revision ./run_ink.sh --fake --autonomy ask
```

1. 等待「就绪」，Enter 生成 v1；在普通输入框写一段中文草稿。
2. `Ctrl+R` → `r` → Enter，进入当前计划的反馈编辑；输入 `将演示内容改为 revised demo`。
3. 点击「下一步」，核对来源和反馈，再点击「确认修订」。Esc 可返回编辑或退出编辑，同一进程内保留反馈和普通草稿。
4. 修订提交后出现 v2；`Ctrl+R` → `b` → Enter 阅读新版，确认验收内容变为 `revised demo` 加换行；`a` 返回动作。窄屏可进入审阅后看版本号。
5. `e` → Enter 批准并执行 v2，两次工具审批分别点击允许，核对「已验证」与 `.vibe/plan-demo.txt` 的实际内容。另开新会话，在写入审批点击拒绝，应保持原文件并显示计划未完成。

取消体验可在命令前加 `VIBE_FAKE_DELAY_SECONDS=3`，确认修订后、提交前按 Ctrl+C。停止后再次进入原卡的修订反馈，点击「续做」才继续；查询结果不调用模型。
脚本使用固定的反馈与产物，验证界面和运行交接，不验证真实模型理解能力。未发送反馈当前只保存在界面进程内；已发送反馈可按下节恢复。完整证据与剩余范围见 [P4 验证记录](../openspec/changes/implement-improve-workbench-ux-p4/verification.md#修订记录与重开恢复2026-11-08)。

### 重开后找回反馈

1. 使用上节带 `VIBE_FAKE_DELAY_SECONDS=3` 的演示，确认修订后、v2 提交前按 Ctrl+C；等待停止。
2. 输入 `/session` 记下会话 ID，再按 Ctrl+Q 退出。在同一工作区运行下列命令，将 `SESSION_ID` 替换为该 ID：

```bash
VIBE_TASK_RUNTIME=1 VIBE_FAKE_DEMO=revision-resume ./run_ink.sh --fake --autonomy ask --session SESSION_ID
```

3. 重开后无需提交新的输入。`Ctrl+R` → `h` → Enter 打开「修订记录」，点击「查看」核对原版本和反馈；读取记录不调用模型。
4. 点击「续做」才继续同一修订任务；提交 v2 后可审阅并执行。已提交的记录提供「新版」，不再提供续做。

`revision-resume` 从修订回复开始播放；新会话请仍用 `revision`。记录可用 ↑↓ 选择，PgUp/PgDn 翻页。原计划被改动时续做会停止，反馈仍可查看；未发送反馈不跨进程保存。

### 核对修订结果的侧栏关联

可先用 `/sidebar` 打开侧栏，再发起计划反馈修订。修订运行期间，侧栏当前对象标为“修订来源”；打开来源正文后等待 v2，原文应保留并提示更新。点击“接入”后显示“修订产物”与 v2 正文。主区修订结果下点击“计划”，应仍进入该产物；费用查询和中文草稿不改变关联。取消后显式续做时，应显示同一修订任务的新运行段。

公开 fake 演示可能很快完成；需要观察运行中的来源可在启动命令前加 `VIBE_FAKE_DELAY_SECONDS=2`。当前进程内关联已通过原生 PTY；重开后的完整历史结果入口仍待实现，重开不会自动续做修订。

## 讲解重点

- 审批不是弹窗装饰：拒绝后副作用必须为零；
- 上下文不是无限堆：1M 也分区，超了先 offload，再 recall，再摘要；
- session 不是聊天记录：它是 append-only 事件日志，崩溃后要能对账；
- eval 不是“感觉能跑”：有 check、trace、cost、regression delta。
