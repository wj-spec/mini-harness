# README 截图指引

这里的 SVG 是明确标注的占位图，不是产品界面。主 README 已预留四个位置；按下表保存真实截图，然后把主 README 中对应的 `.svg` 改成 `.png` 即可。无需改动布局。

| 文件名 | 建议展示什么 | 如何进入这个画面 |
| --- | --- | --- |
| `workbench.png` | 项目名、已连接模型、一段简短编码对话；让读者一眼看懂这是终端 Coding Agent | 在公开示例仓库运行 `mini-harness`，完成一次“解释项目入口”的对话后截图 |
| `plan-review.png` | 一份包含 3–5 步的计划，能看到目标文件和验收方式 | 请求先制定修改计划；在待审阅状态截图，或执行计划时用 Ctrl+L 打开完整清单 |
| `approval.png` | 一次范围清楚的文件修改或命令，显示审批内容与允许 / 拒绝操作 | 使用 `mini-harness --demo`，发起预填任务，在审批出现时截图 |
| `verification.png` | 完成后的验证回执，最好包含测试结果与改动摘要 | 完成 Demo 或公开仓库中的小修改，截图最终回执；需要补充详情可打开 `/evidence` 或查看 diff |

## 拍摄建议

- 主图建议 1600 × 900 或接近 16:9；三张功能图尽量保持相同尺寸和字体大小。使用 PNG，保留原始清晰度，不要把小图放大。
- 统一终端主题、字号和窗口宽度。文字必须能在 GitHub 页面上读清；重点信息放在中间，裁去多余空白。
- 使用公开示例项目和简短任务。截图前核对 API Key、服务地址中的敏感信息、私人路径、仓库内容与会话记录。
- Demo 图保留“测试模型 / Demo”标识，不将本地演示呈现为真实模型能力证明。
- 首页主图展示实际使用场景；安装报错、空白首页和内部验收日志不适合作为主要展示图。

## 替换步骤

1. 将四张图片保存到本目录，使用表格中的文件名。
2. 在仓库根目录 README 中搜索 `SCREENSHOT` 注释，找到主图和三张功能图的引用，把后缀 `.svg` 改为 `.png`。
3. 删除首页“以上为明确标注的截图占位”那一段；如果只补了部分图片，改成说明剩余截图位。
4. 在 GitHub 或支持 GitHub Markdown 的预览中检查图片比例、文字清晰度和三栏排版。
5. 全部换好后，可以删除不再使用的 SVG。已有 `docs/assets/workbench.png` 是早期界面参考，确认不再需要后再移除折叠参考区。

以后只更新 PNG 文件即可，不必再次改 README 引用。可选录制一段 20–40 秒的真实终端演示，依次展示任务 → 审批 → 验证，并在 README 主图下附链接。
