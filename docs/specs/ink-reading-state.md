# Ink：历史滚动与 Agent 状态分区

日期：2026-10-21。状态：工程实现、自动回归、本地 PTY 与实际组件画面检查完成；用户终端与真实模型体验待验收。用户反馈对话区不能上下滚动，且展示缺少重点与分区。

> 2026-10-23 更新：Textual 已退役，Ink 是唯一界面入口；文中“保留 Textual 入口”为当时记录。

## 行为

- 在对话阅读区内用滚轮 / 触控板浏览历史；阅读工具详情与审批预览时同样可以滚动。连续滚动事件逐次累加，不被同一次渲染覆盖。
- `PgUp/PgDn` 翻页、`Ctrl+P/N` 或 `Ctrl+↑/↓` 逐行滚动。`Ctrl+R` 切换阅读 / 输入焦点；阅读焦点下 `↑↓` 逐行、空格下一页、`Home/End` 到首尾，`Esc` 返回输入。
- 回看期间新输出不抢走位置，显示滚动位置、下方还有多少内容与返回最新入口。滚动不修改草稿，审批不会因鼠标包或粘贴内容被批准。
- 鼠标监听限制在阅读区，退出关闭终端鼠标模式；没有鼠标报告的终端使用键盘滚动。终端支持时用 Shift 拖选文本。
- 按实际事件区分等待模型、生成回复、执行工具、等待审批、正在停止、暂停、错误与断开。使用明确文字和语义颜色，不虚构思维链或任务完成百分比。
- 用户任务、助手回复、工具与执行结果、重要提示分块展示。失败、超时、取消、结果未知分别表述。较宽终端展示侧边状态区；窄屏使用紧凑状态条，输入和关键操作保持可见。
- 预算条读取后端真实用量与上限；计划只能展示后端已记录的数量，不将模型一轮结束当作需求完成。

## 验证

先复现滚轮无效及没有阅读焦点的失败回归，再实现。覆盖连续滚动、跨帧新输出、草稿保护、审批与粘贴隔离、鼠标区域和退出恢复；检查 80×24、120×40、48×18、32×12 的布局，以及运行 / 审批 / 错误等实际组件渲染画面。

运行产物写 `.vibe/ink-reading/`。默认入口继续保留 Textual，直到 Ink 的开发与实际体验超越 Textual；本轮不切换入口，不改变模型或审批策略。真实终端输入法、触控板设置和真实模型任务单独验收。

## 实现与结果

全屏终端没有原生 scrollback，原先仅处理翻页键，缺少滚轮协议。新增 `mouse.ts` 解析 SGR 滚轮，`use-transcript-scroll.ts` 处理命中区域与鼠标模式生命周期；App 用同步视口引用累加同一批滚动，避免只保留最后一个事件。

额外复现了 Ink 将间隔超过 20 ms 的未完成鼠标包按文字发送的路径。`terminal-input.ts` 通过公开的 `render({stdin})` 包装输入流，将已识别的 SGR 前缀缓冲到完整后发送，保持普通 UTF-8、键盘和粘贴原样。缓冲有界，退出清理监听；未修改 Ink 私有实现或真实 stdin 的方法。单独 Esc 与任意迟到字符的终端歧义不作无限等待。

`view-state.ts` 保存实际 activity、信息命令类别、最后运行状态与停止原因；`agent-status.tsx` 据此展示状态、当前任务、工具实况和资源用量。消息与工具结果独立卡片；异常状态放在工具名称前，长 MCP 名称不能挤掉退出结果。失败与断开时输入区说明重新启动，避免误导用户等待不存在的任务。

## 底色层级调整（2026-10-21）

根据“框线太多、视觉疲劳”的后续反馈，移除对话、输入、状态栏和消息块的围框及横向分割线。普通 Agent 回复沿用主底板；用户任务、工具、代码、输入与侧栏通过底色深浅及留白分层。选中工具保留箭头与详情提示，其余工具省去重复快捷键提示；失败与审批使用轻染色和明确状态文字。终端通过实色背景模拟层次，不使用网页式模糊阴影。

浅色和深色主题分别配置完整前景与背景，自动回归核对所有正文、辅助与语义前景在各底色上的对比度不低于 4.5。`system` 读取 `COLORFGBG` 的已知浅色提示；缺失或未知时回退深色，可用 `/theme light` 覆盖。颜色能力由 Ink 按终端降级，文本标签仍独立说明状态。默认入口继续保留 Textual。

阅读区和输入区以等量 padding 替代原边框，保留窗口尺寸、鼠标命中与焦点规则。实际组件浅色 / 深色运行场景、80 列审批和断开场景保存在 `.vibe/ink-reading/tonal-*.ansi`、`.svg` 与 `.svg.png`。复现可在上述 fixture 命令后追加 `--theme=light` 或 `--theme=dark`；`--snapshot` 输出实际组件的静态终端画面。

本次当前工作树验证：`npm --prefix tui test` **144 passed**；完整 Python 回归 `./run_tests.sh -o addopts='' -q` **562 passed**。最后的状态区留白与长工具名调整另通过 6 项状态区测试。浅色 / 深色在无色、16 色和 256 色输出下保留状态文字；原生能力降级不保证还原所有细微底色。

恢复展示改从 `SessionStore.load_messages()` 读取原始日志，保留压缩前的正文、各轮任务、工具调用和结果。没有原始记录的程序化恢复仍回退已有上下文。`Agent.history` 继续从 `load_context()` 读取压缩快照及后续消息，不重新塞入全部原文，也不自动调用模型或重放工具。恢复提示显示日志条数。

新增 `--list-sessions` 只读列出会话 ID、完整消息数、消息更新时间和首条用户标题；无需 TTY、API key 或模型 / MCP 初始化。`--session ID` 精确打开本工作区中的旧会话，与 `--continue` 互斥。`--continue` 仍只选择最近有对话的会话，不启发式跳过短会话或合并会话；排序改看有效消息事件时间，避免目录附件或打开操作改变选择。列表过滤控制字符，ID 限于本工作区单目录，读取不改原日志。

## 测试会话用途隔离（2026-10-21）

用户要求测试记录必须有标识，正常使用不能加载。`SessionStore.new` 新增显式 `purpose="user" | "test"` 并写入元数据；`latest`、`list_sessions`、`open_existing` 都按同一用途范围过滤，普通模式指定测试 ID 也不能绕过。测试模式同样不能加载用户会话，避免伪回复写入真实历史。消息长短、正文关键词和模型名称不参与用途推断。

CLI 在 `--fake`、fake provider 配置或 `--test-session` 时进入测试范围，其他情况使用用户范围。直接 stdio 的 FakeProvider 兜底建会话也标记为测试。列表显示 PURPOSE，ready 提供可选 session_purpose，Ink 与 Textual 标题明确显示“测试会话”；老后端缺少该字段时仍可读取。旧元数据没有用途时兼容用户会话，存在但损坏、未知用途或符号链接的元数据跳过。

本工作区三条已确认的 context 烟测记录已定点补 `purpose=test`，元数据原件和迁移清单存入 `.vibe/session-scope/`。未删除记录，消息日志 hash 保持不变；不批量猜测其它旧会话。生产普通列表隐藏三条测试记录，逐条按 ID 打开均在模型初始化前拒绝；默认 latest 已回到 `20261020-224244-563557` 的 219 条用户记录。显式测试列表单独可见这三条。
