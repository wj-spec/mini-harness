# Ink：复制 Agent 输出

日期：2026-10-23。状态：工程实现与自动回归完成；真实终端复制体验待用户验收。

## 背景

Ink 使用全屏 alternate screen，并在阅读区开启鼠标追踪实现滚轮回看；这会让终端原生拖选复制失效，用户无法取走 Agent 的最终回复或工具输出。2026-10-23 用户反馈“无法复制”。

## 行为

- `Ctrl+Y` 或 `/copy` 复制当前最有用的内容，按优先级：
  1. 工具详情打开时：该工具的完整参数摘要与输出；
  2. 审批面板打开时：审批预览（命令 / 写入 diff / 搜索词）；
  3. 其余情况：最近一条 Agent 回复的 Markdown 原文。
- 复制成功后在 notice 区显示“已复制<目标>：N 字符（方式）”；没有可复制内容或剪贴板不可用时明确提示，不静默失败。
- 复制是本地只读操作，不调用模型、不经过审批，也不修改对话或会话记录。
- 单次最多 1 MiB（按 UTF-8 字节）；超出时截断到上限并在提示里说明。

## 剪贴板机制

按顺序尝试，均失败时返回不可用：

1. 本机剪贴板命令：macOS `pbcopy`；Windows `clip`；Linux `wl-copy` → `xclip -selection clipboard`。
2. OSC 52 转义序列（`ESC ] 52 ; c ; <base64> BEL`）写入 stdout，供支持该协议的终端 / SSH 会话使用；tmux 需要开启 `set-clipboard`。

不新增运行时依赖；实现集中在 `tui/src/clipboard.ts`，App 通过可注入的 `copyText` 调用，测试不触碰真实剪贴板。

## 边界

- 终端或 tmux 不支持 OSC 52、且本机没有剪贴板命令时，只能提示失败；不把内容写到其它文件。
- 不实现区域选择/多行复制；先覆盖“取走整段输出”这一真实需求。原生拖选仍可通过终端自身设置或关闭鼠标追踪实现。
- 复制内容受 Ink 已保存的 entries 限制：被阅读区截断显示的长消息仍按完整原文复制。

## 验证

- 单元测试：macOS 命令优先、Linux 命令失败后回退 OSC 52、空内容返回不可用、超大文本截断。
- Ink 交互测试：`Ctrl+Y` 复制最近回复并提示；`/copy` 等效；无内容时提示；既有测试全部通过。
- 文档：USAGE 键位表、CLI `--help` 与 `/help` 补上 `/copy` / `Ctrl+Y`。
