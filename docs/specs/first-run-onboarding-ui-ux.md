## 1. 要解决什么

用户希望从自己的项目和真实模型开始使用；首次进入时，界面应帮助补齐必要配置，并说明下一步。当前验收入口预置 MCP，启动后立即出现启动命令审批，用户尚未理解服务用途就被要求做决定。截图还显示初始界面同时呈现长路径、模型/provider、授权层级、上下文构成、token 和任务统计，主次不清。

目标是把真实使用过程连起来：

**启动产品 → 识别配置状态 → 必要时补齐模型连接 → 确认当前项目 → 发出第一个真实任务 → 审批具体操作 → 看懂结果。**

成功标准不是新增页面数量，而是用户无需理解 .env、MCP 或内部协议，就能完成一次真实任务，并且知道配置是否保存、检测了什么、当前用了什么模型。

### 1.1 当前事实与拟新增能力

| 部分 | 当前已有 | 本方案拟改变 |
| --- | --- | --- |
| 正常启动 | ./start.sh 先准备依赖，缺 Key 时进入终端问答式向导 | 依赖就绪后进入 Ink；必要模型配置由界面引导 |
| 模型设置 | /model 已有来源、隐藏 Key、保存、检测、应用；各动作分开 | 首次配置提供连续路径，日常设置继续保留独立操作 |
| 模型初始化 | 构建真实 provider 前要求 Key；现有设置依赖运行中的 Agent | 增加只处理配置的启动状态，准备好后初始化真实运行环境 |
| 首页和指引 | 有金渐层像素猫、功能区指引和任务示例 | 强化主要动作、配置状态和真实项目入口，降低初始技术信息密度 |
| MCP | 有基础/高级编辑、逐服务/全部重连与断开；配置服务启动时尝试连接 | 交互式前台启动默认不自动连接，连接由明确用户动作触发 |
| 验收 | --acceptance 使用隔离配置、Demo 和本地 MCP | 明确标为测试入口；本方案的主要验收走普通启动和真实模型 |

上述事实基于当前工作区，而非已发布版本。现有工程基线为 Python 2060 passed / 4 skipped、Ink 802/802；这不是本方案的实施或验收证据。

### 1.2 范围

包含：正常启动分流、首次模型配置、连接状态、项目确认、空白对话引导、设置首页、MCP 主动连接、审批信息层次、键盘/鼠标/窄屏体验，以及真实旅程验收。

沿用：Ink 唯一界面、现有 Logo、ApprovalGate、配置优先级、任务快照、后台隔离、回执分层与证据入口。

不包含：新 Web/桌面界面、账号/云端同步、模型市场、自动付费调用、自动安装 MCP、重新设计权限引擎、后台配置热更新、会话内随意切换工作目录、遥测系统或 Logo 重画。

## 2. 核心设计原则

1. **先解决用户当下的阻塞。** 没模型时帮助连接模型，尚未开始任务时帮助表达任务。
2. **必填项尽量少。** 默认服务通常只填 Key；预算、MCP、沙箱、通知不阻塞首次使用。
3. **已有配置不重复打断。** 不以“第一次见到此版本”为理由强制重新走向导。
4. **状态必须有依据。** 已配置、检测通过、当前生效、工具能力已验证分别表达。
5. **默认走真实使用。** Demo 是明确的次要选择，不因缺 Key 自动伪装成可运行助手。
6. **审批跟随用户意图。** 用户选择连接服务后才出现启动审批；不降低审批边界。
7. **高级信息可找到，但不抢主操作。** 功能隐藏在有标签的详情里，不删除证据。
8. **返回与失败不丢编辑。** 提交成功只处理对应版本的草稿，不清空后续修改。

## 3. 启动分流与状态

### 3.1 何时出现引导

| 情况 | 首屏 | 是否阻塞发送任务 |
| --- | --- | --- |
| 未配置或明显占位 Key | 首次模型连接页 | 是，可选择稍后配置或 Demo |
| 地址/模型等本地格式不完整 | 配置页并定位具体字段 | 是 |
| 已配置且本地格式有效 | 真实工作台，轻量显示“已配置 · 尚未检测” | 否，不自动发测试请求 |
| 当前进程显式检测成功 | 工作台显示“连接检测通过” | 否 |
| 显式检测失败 | 留在配置页显示可处理的错误 | 可修正、重试、稍后配置；已有效配置可明确选择跳过检测继续 |
| 配置文件损坏/不可读 | 配置问题页，显示位置与修复方法 | 禁止盲目覆盖；原文件保留 |
| 打开另一个项目、模型配置仍有效 | 新项目首页，显示当前工作目录 | 不重复模型向导 |
| 显式 --demo / --fake | 标注“Demo · 不调用真实模型” | 按演示流程运行 |
| 显式 --acceptance | 标注“隔离验收环境”，与普通入口区分 | 不能替代真实模型验收 |
| 非交互环境 | 明确错误及可执行的配置命令 | 不启动交互页面，不等待不可见输入 |

“首次”根据必要配置是否完整判断，不靠单独的 onboarding_done 布尔值。新会话/升级不会因此强制重跑向导。

### 3.2 配置、文件和检测分开

- **草稿**：尚未保存，保留在本次界面内。
- **已保存**：对应文件写入成功；不代表网络可用或当前运行环境已切换。
- **检测通过**：针对指定配置的一次最小请求成功；不代表所有工具调用、长任务或模型能力可用。
- **当前生效**：真实运行环境已使用该配置，可开始新任务。
- **待应用 / 受覆盖**：文件与当前值不一致，或 CLI/进程环境仍优先。

连接检测结论只在当前进程内关联确切配置版本。地址、模型、Key 或代理变化后，旧结论失效；迟到回执不能把新配置标为通过。重启后不把历史成功直接显示为“现在可用”，不持久化明文 Key 或可离线猜测的 Key 摘要来证明健康状态。

## 4. 首次配置页面

使用主区域内的专注页面，而非盖在空白工作台上的多层弹窗。保留小猫与产品名，隐藏任务侧栏和技术仪表；用户始终看得到当前步骤、主要按钮和退出方式。

### 4.1 标准尺寸线框（示意，不是已实现界面）

~~~text
Mini · 陪你完成第一个编码任务

1 连接模型   →   2 确认项目   →   3 开始任务

连接一个模型
选择服务后，通常只需填写 API Key。

模型服务     [ DeepSeek                    ▾ ]
API Key      [ •••••••••••••••••••••••••••• ]

默认地址与模型已填好
[ 自定义模型、地址与代理 ▸ ]

[ 保存并检测 ]   [ 稍后配置 ]
~~~

### 4.2 字段与行为

| 字段 | 默认展示 | 行为 |
| --- | --- | --- |
| 模型服务 | 始终显示 | 首版沿用已有默认服务和“自定义 OpenAI 兼容服务”，不扩展未经验证的服务列表 |
| API Key | 始终显示，隐藏内容 | 支持粘贴；已有 Key 显示“已配置，留空保留”；不会从后端回传原值 |
| 服务地址 | 默认服务折叠，自定义服务展开 | 显示示例和用途；禁止包含账号密码、查询凭据等不支持内容 |
| 模型名 | 默认服务折叠，自定义服务展开 | 默认值来自已有启动配置，不把静态列表冒充最新模型目录 |
| 环境代理 | 高级项 | 显示开关和作用；默认沿用已有行为 |
| 配置来源 | 简要状态 + 详情 | 首屏提示“使用环境配置”等必要结论；完整来源/路径可展开 |

每个字段有独立标签和短说明；不依赖占位文字表达字段含义。校验错误显示在字段附近，并在提交时把焦点定位到第一个错误。粘贴完整 Key 不触发快捷操作、不显示剪贴板内容。

### 4.3 主要动作的明确语义

首次页面的“保存并检测”是一个连续交互入口，内部仍按现有权限边界分步执行：

1. 本地校验；失败不写入、不联网。
2. 展示保存目标与非敏感摘要，通过 ApprovalGate 原子保存。
3. 明确提示即将检测的服务和最小请求，通过相应网络审批。
4. 执行检测，显示“正在检测……”及取消入口，禁止重复提交。
5. 成功后进入“确认项目”；失败留在当前页，明确标注“已保存，检测未通过”。

网络审批拒绝或检测失败不会伪称整个操作未发生；已经保存的配置不自动撤回。保存失败则不继续联网。若取消时写入已成功，回到页面后必须展示这一事实。

首次配置可在次要操作中“仅保存，稍后检测”；本地有效但未检测的配置允许用户明确继续，首个真实请求失败后再提供修复入口，不强制每次启动都发测试请求。

日常 /model 保留“保存”“检测”“应用”的独立操作，以免修改一个设置自动切换正在使用的模型。

### 4.4 生效与覆盖

- 首次无运行环境时，选择“进入项目”才初始化真实 provider；不会先创建 FakeProvider 再偷偷替换。
- 新环境准备失败，保持配置页并显示原因，不把“保存成功”当作“可开始任务”。
- 已有运行环境使用原配置时，明确列出当前值与待应用值；运行中不能替换客户端。
- CLI/进程环境优先于文件。界面提示哪个字段被覆盖，以及文件保存后为什么没有改变当前值。
- 不允许用新地址静默携带受环境固定的旧 Key；沿用现有跨服务凭据保护。
- Demo、自定义 provider、额外审计客户端或其他不能安全切换的情况，明确要求保存后重启，不宣称支持热切换。
- 旧任务续做仍核对模型快照，后台进程不随前台设置自动变化。

### 4.5 稍后配置与 Demo

“稍后配置”进入可浏览的工作台，显示一条“连接模型后即可发送任务”提示和明确按钮；可以输入并保留任务草稿，但不能提交真实任务。不会触发虚假的运行进度。

“先体验 Demo”必须显式选择，并持续显示 Demo 标识。演示上下文与真实会话隔离；从 Demo 转到真实使用时通过受控重启/新会话进入，首版不把演示记录混入真实会话。

## 5. 项目确认与真实首页

### 5.1 首次连接后的确认

~~~text
连接检测通过

接下来，在这个项目里开始
mini-harness
/Users/…/mini-harness             [ 查看完整路径 ]

我可以阅读项目、提出修改，并在需要时请求你审批操作。
确认目录不等于授权读取全部文件或执行命令。

[ 进入项目 ]   [ 返回模型配置 ]
~~~

使用当前启动目录或 --workspace 指定目录，不重复输入。该步骤不修改授权、不发模型请求、不扫描整个仓库。

本轮不提供已运行会话内直接改工作目录。目录错误时，明确说明如何在目标目录启动或使用 --workspace；防止一个会话的上下文、文件和审批指向不同项目。

### 5.2 已配置用户的正常首页

~~~text
Mini · 今天准备做点什么？

项目  mini-harness                         [ 查看项目 ]
模型  deepseek-flash · 已配置，尚未检测       [ 更改 ]

[ 了解这个项目 ]   [ 定位一个问题 ]   [ 实现一个修改 ]

告诉我你想完成什么，也可以从上面的示例开始。

> 输入你的任务…

[ 设置 ]  [ 功能指引 ]
~~~

- 已配置用户直接看到此页，不出现步骤向导，不自动检测。
- 示例只填入可编辑草稿，不自动发送、不自动调用工具。
- 当前已有草稿时，不覆盖或悄悄追加示例；保留草稿并提示可先清空再使用示例。
- 项目名优先显示，完整路径按需查看；路径尾部可截断，详情可阅读。
- 尚未发出任务时，首页不常驻上下文拆分、token 分布、费用和内部状态码。
- 首个任务开始后自然切换到现有对话工作台，不在每轮结束后重新展示欢迎页。
- 切换模型、检测失败或 MCP 未连接使用轻量状态提示，不抢占已有对话。

### 5.3 已有会话与进程恢复

- 恢复会话时优先展示历史与任务状态，不回到欢迎页。
- 模型缺失或不匹配时保留历史和输入，提示进入设置；不自动重跑旧任务。
- 自动跳转配置只针对确实阻塞首次发送的必要项；首次真实请求的鉴权/网络失败提供“修复连接”按钮，避免突然跳走覆盖用户阅读。
- 设置关闭后恢复原草稿、光标和阅读位置；窗口尺寸变化不丢失这些状态。

## 6. 设置中心的信息架构

设置首页改为按用户目标选择分类，而非首先呈现一组数字参数。

| 分类 | 摘要 | 进入后的重点 |
| --- | --- | --- |
| 模型连接 | 当前模型、来源、检测状态 | Key、地址、模型、代理；保存/检测/应用边界 |
| 任务预算 | 新任务单段限制、目标总预算 | 数值、单位、默认值和旧任务快照 |
| 外部工具 | 已配置 N 个，已连接 M 个 | MCP 服务列表、连接/断开、配置与高级字段 |
| 权限与安全 | 当前审批方式、权限来源 | 有效授权、撤销；不使用“已安全”这类笼统结论 |
| 更多设置 | 通知、沙箱及需重启项 | 已支持项和生效范围；不能编辑的项提供具体说明 |

进入分类后保留现有能力，不在本轮扩张沙箱或通知编辑器。现有 /model、/mcp edit、/permissions 等直接命令继续可用，旧快捷键在对应子页中兼容。

状态词与颜色配合使用：

| 状态 | 含义 | 后续动作 |
| --- | --- | --- |
| 未配置 | 必要信息缺失 | 配置 |
| 已配置 · 尚未检测 | 本地信息完整，没有本次检测证据 | 检测 / 直接开始 |
| 检测通过 | 当前配置的最小请求通过 | 进入项目 / 开始任务 |
| 检测未通过 | 本次检测失败 | 修复 / 重试 |
| 待应用 | 保存值不同于当前生效值 | 查看差异 / 应用或重启 |
| 受环境覆盖 | 文件值不是最终生效值 | 查看来源 |
| 未连接 / 已连接 | MCP 实际连接状态 | 连接 / 断开 |
| 待重载 | MCP 保存值与运行值不一致 | 重载所选服务 |

预算等不涉及网络的分类不使用“检测通过”。状态说明应符合对象，不做一套含义模糊的通用绿灯。

## 7. MCP：先理解，再连接，再审批

### 7.1 启动策略

**本方案建议：普通交互式 Ink 前台默认不自动启动 MCP，即使已有配置。**

- 启动只读取必要配置摘要；首页可以轻量显示“有 2 个外部工具服务尚未连接”。
- 用户进入外部工具并点击某个服务的“连接”，才发出启动请求并进入审批。
- 没有 MCP 配置时，不显示无意义的待办，不要求首次用户添加 MCP。
- 不因模型第一次打算调用工具而暗中启动服务；首版不做自动延迟连接。
- 已有服务用户仍可显式“连接全部”，先看清范围，再按各服务的审批处理；不能借批量按钮自动扩大授权。
- 本轮不新增默认自动连接白名单。若以后有明确需求，再单独设计 opt-in 策略。
- 后台 worker、非交互 CLI、eval 保持原合同，不能因前台 UX 调整被顺手改变。
- --acceptance 先显示“验收环境 · 隔离配置”标识与隔离说明（Demo 模型、本地 MCP、不读取现有 .env）；MCP 初始未连接，验收时由用户打开 /mcp 选择连接。已实现。

### 7.2 服务列表与详情

~~~text
外部工具

alpha     本地回显服务      未连接          [ 连接 ]
beta      本地回显服务      未连接          [ 连接 ]

[ 添加服务 ]   [ 连接全部 ]

这些工具是可选的，不影响普通对话。
~~~

服务用途必须有可靠来源。本地内置验收服务可写“本地回显服务”；其他服务若未提供说明，只展示配置名称和可核对的命令摘要，不能根据名称编造能力或安全承诺。

点击服务详情后展示常用配置、状态、当前操作范围；高级参数折叠。当前/全部范围既有行为继续保留，不能因为选中项消失而把单服务操作降级成全部。

### 7.3 审批呈现

~~~text
连接外部工具：alpha

将启动一个本地程序，并读取它提供的工具列表。
该服务将用于：本地回显演示
范围：仅 alpha；beta 不变

[ 查看完整命令、工作目录与权限详情 ▸ ]

[ 允许本次操作 ]   [ 暂不连接 ]
~~~

- 保留工具层级、完整命令、cwd、环境键、来源范围与权限证据；详细信息可展开和滚动。

## 8. 视觉与交互规范

### 8.1 信息层级

1. 当前目标与主要动作：连接模型 / 进入项目 / 输入任务。
2. 必要状态：配置是否完整、当前项目、失败原因、操作范围。
3. 可选帮助：示例、来源、完整路径、权限解释。
4. 技术详情：provider 标识、协议动作名、上下文分布、token 明细、trace。

初始页面只常驻前两层，后三层按需展开。运行中的取消、审批与真实失败不能因精简而隐藏。

### 8.2 视觉语言

- 沿用胖脸金渐层像素猫与现有主题；猫作为识别元素，不占据半屏或推动控件跳动。
- 主操作使用现有 accent/focus 色，正文使用 foreground，说明使用 secondary，错误/待确认使用 warning；避免新增随意硬编码色。
- 成功/失败同时提供文字与符号，不能只靠颜色。
- 表单标题、输入值、辅助说明、错误和操作区有稳定顺序；避免大段连续技术文本。
- 一屏一个主要动作；危险或全量操作清楚标记，不能与“继续”使用相同默认焦点。
- Loading 不改变按钮位置和整页高度；保留可取消路径，不通过持续闪烁强调状态。
- 首次配置不显示任务成本仪表；真实任务开始后沿用现有状态区和详情入口。

### 8.3 键盘、鼠标和尺寸

| 场景 | 要求 |
| --- | --- |
| 80×24 | 完整展示主要字段、当前反馈与主要动作；说明区可滚动 |
| 120×40 及以上 | 扩大说明与阅读区域，不把所有高级信息自动展开 |
| 32×12 | 单列紧凑模式，一次聚焦一个字段；步骤缩为“1/3”，操作可分页/滚动，当前焦点始终可见 |
| 小于最低尺寸 | 明确提示调整窗口，输入与配置草稿保留 |

- Tab / Shift+Tab 按视觉顺序移动；Enter 对当前焦点操作；Esc 结束编辑或返回上一层。
- 列表方向键导航与输入框光标移动分开，不能在粘贴或编辑时触发全局快捷键。
- 主按钮和折叠项可点击，有明确选中反馈；不依赖鼠标悬停。
- 兼容现有审批按键，不在文字输入中抢占 y/n；输入法、中文、长路径和粘贴都纳入测试。
- 说明区支持滚动；布局调整后焦点、草稿、光标和阅读位置稳定。
- 首版不声称完成屏幕阅读器认证；使用清楚文字标签、自然读取顺序和现有纯文本终端能力，并保留实际辅助技术验证项。

## 9. 异常、恢复与并发

| 情况 | 必须看到的结果 |
| --- | --- |
| Key 空或占位 | 对应字段提示，不联网 |
| 地址格式错误 | 定位地址字段，不显示 URL 中被拒绝的凭据 |
| 401 / 403 | 说明凭据或访问权限问题，保留输入，提供编辑入口 |
| 模型名不支持 / 响应不兼容 | 区分可辨识问题与通用错误，不凭状态码推断唯一原因 |
| 超时 / 网络 / 代理错误 | 允许重试、调整地址和代理；不自动无限重试 |
| 429 / 服务端异常 | 提示稍后重试，不要求用户盲目换 Key |
| 文件版本冲突 | 原文件保留，刷新后核对；草稿不丢 |
| 保存被拒绝或权限不足 | 不联网、不应用，保留输入 |
| 保存成功后检测被拒绝 | 明确“已保存，未检测”，允许稍后继续 |
| 检测期间取消 / 退出 | 取消请求并忽略迟到回执；说明已发生的保存 |
| 重复点击 / 按回车 | 一个待处理操作；无重复保存或测试调用 |
| 打开设置时有任务运行 | 可读/编辑草稿；运行参数切换受后端互斥保护 |
| MCP 文件损坏 | 外部工具页显示配置问题，不让可用模型的首页崩溃 |
| 后端断开 | 明确断开，保留本次前端草稿；重启后不自动重放写入/连接 |
| 来源变化 / 切换会话 | 旧响应按请求、工作区、会话、配置版本过滤，不覆盖新状态 |

原始服务错误不可直接渲染，避免回显 Key、请求头和响应中的敏感信息。仅显示可安全分类的原因；开发诊断沿用现有脱敏规则。
