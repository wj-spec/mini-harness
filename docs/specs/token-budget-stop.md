# W1 切片：预算收敛与暂停

本页记录初版“80% 后收尾暂停”的行为与验证。根据后续实际使用反馈，现行策略已改为 [自动压缩继续与交互可靠性](practical-use-reliability.md)：交互任务累计预算默认不限（0）；显式设置硬预算时，只有余额不足才收尾暂停，且压缩目标不再随累计余额缩小。

## 目标

保留默认单次 run 的 200k 累计 token 预算，让用户看见消耗，并在停止后拿到可恢复的进展。

## 行为

- 展示累计输入、输出、上限和剩余；提供方缺 usage 时采用估算并明确标注。
- 已用达到 80%，或预计下一次常规请求将耗尽余额时，转入一次无工具、精简上下文的进展收尾。余额不足时直接保存本地暂停说明。
- 收尾前执行 [history 滑动窗口与分层摘要](history-compression.md)，保存工作上下文快照；收尾同时遵守累计预算与单请求窗口限制。
- 不为了收尾放宽预算。用量在完整响应后更新，因此实际用量仍可能整轮越过上限；这是软预算保护。
- 超限时保存已生成的 assistant 内容；请求的工具均记为未执行并补齐协议结果，避免恢复时误认为已做或产生悬空调用。
- 暂停说明列出任务、已记录的进展及待核对事项，不把尝试过的文件或命令当作成功证据。
- 持久化停止原因与预算快照；`--continue` 遇到明确的 stopped run 先展示状态，`/resume` 才启动新一轮预算。没有终态记录的崩溃恢复保持原流程。

## 验证

先补失败测试：末轮文本保留、未执行写入/命令与工具配对、预算收尾禁用工具、没有余额不请求模型、估算 usage、暂停会话不自动续跑、显式恢复可用。对原会话用量做离线回放，确认能提前收敛。

本轮不开发 MCP 接入，也不改变写入和命令的审批规则。可信命令结果仍是后续切片。

## 实施验证

- 初版完整测试 149 项通过；加入 history 分层压缩与窗口边界后，完整测试 206 项通过，包含首轮长历史压缩后的预算预检、中断响应保留、无 usage 估算、工具配对与禁止执行、收尾异常不重试等回归。
- 用原运行前八轮的累计 usage 回放，第八轮 166,877 后进入无工具收尾；测试脚本给定收尾 400，得到 167,277。这个数字验证控制流，不预测真实模型的最终用量。
- 用原 208,401 会话的副本验证打开后不请求模型；原会话未修改。fake CLI 启动、退出通过。
- 尚未重跑真实模型的 MCP 开发任务，不据此标记 W1 或 MCP 接入完成。
