# W1 切片：可信命令结果

## 用户目标

文件操作已能使用。下一步让助手根据实际验证结果继续工作，交付能与执行记录核对。

状态：工程实现与确定性回归已完成，真实模型任务待验收。

## 原有差距

- `app/tools.py` 的 bash 返回 `exit=N` 文本；执行包装只要函数正常返回就给出 `ok=True`，非零退出尚未反映到执行状态。
- `TaskState.tests_run` 把所有 bash 调用记录为测试命令，未保存退出结果。
- `AgentResult.status=done` 表示这一轮模型结束，不能单独作为测试通过或需求验收的证据。

## 本切片的行为

1. 命令结果能区分零退出、非零退出和超时，保留实际输出及可获得的退出结果。
2. 模型与任务记录接收同一份实际执行结果；失败可以驱动下一轮修正。
3. 任务记录区分“执行过命令”与“验证通过”；普通命令不会被自动视作测试。
4. 最终说明能核对执行了什么、成功还是失败、哪些验证尚未进行；未运行的验证不能标成通过。

## 验收

- [x] 先补失败测试：执行 `exit 1` 后，工具结果与任务记录均反映失败，模型下一轮能看到它。
- [x] 零退出结果与输出仍正确回灌；超时、取消与未知结果也明确记录。
- [x] 确定性 provider 演示“测试失败 → 审批修改 → 重新运行通过”，实际进程结果与记录一致。
- [x] 写文件与执行命令仍经过 ApprovalGate；本切片不改变审批规则。
- [ ] 用真实模型完成同类小任务，并核对最终交付。

## 工程证据

`tests/test_command_results.py` 覆盖真实零 / 非零退出、伪造输出不能覆盖退出码、超时、取消与回收、失败后审批修复再验证；普通命令不会自动进入测试记录。`verification:true` 仅声明测试 / 构建 / 检查用途，退出结果仍由真实进程决定。

`Message.execution` 随消息、压缩检查点和磁盘归档保存。`tests/test_execution_persistence.py` 覆盖重开会话、压缩后取回证据、非法退出元数据与旧记录兼容；提供方请求不会包含本地元数据。Ink 按这些状态展示命令卡片，不从工具输出文字推断成功。

## 边界

复用现有工具、TaskState、trace 和 TUI；只增加验证结果所需的数据。原生命令超时和取消会回收进程组，保留部分输出及可获得的退出码；结果缺失时保持未知。W2 的运行中纠偏与更完整停止验收仍单独推进。
