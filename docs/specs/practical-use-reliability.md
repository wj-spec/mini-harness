# 实际使用可靠性：审批、等待、压缩继续

## 反馈与决定

使用反馈集中在审批频繁、审批等待影响运行时限、取消后页面无法输入，以及预算提示反复要求继续。已确认的行为是：压缩后自动继续，任务总预算提高到 1M。下表保留问题、原因与行为决定，原始随手记录仅留本地。

| 使用问题 | 已核对的原因 | 本轮行为 |
|---|---|---|
| 审批频繁 | 原 s 精确匹配工具与文件或命令；一段实际会话 33 条不同 bash 命令产生 33 次提示 | 提供明确的工作区授权、精确规则及撤销入口 |
| 审批等待像超时 | 审批自身无截止时间，但人工等待计入 max_run_seconds | 人工等待排除在运行时限外，模型与命令保留各自超时 |
| 页面无法输入 | 审批弹窗吞 Ctrl+C，worker 取消后可能留下孤立弹窗 | 弹窗支持取消，finally 清理弹窗并恢复输入 |
| 反复要求 /resume | 80% 原先直接转换收尾暂停 | 压缩与任务总预算独立，压缩后留在同一 run 继续 |

卡住已由取消与弹窗生命周期问题复现，修复在当前 Python/Textual 实现中完成；本轮不进行 TypeScript 框架迁移。状态栏改为分行显示任务、上下文与项目，审批标题避免重复展示大段待写内容。完整视觉设计继续根据使用反馈迭代。

## 权限

- y/a 仅本次；s 允许本会话此工具与此文件、此目录下同一命令，或远端工具同一组参数。
- p 允许本进程、当前工作区发起的内置 write_file/edit_file/bash；MCP 仍独立审批。每次执行仍通过 ApprovalGate 并审计。
- 文件路径与工作区规范化，命令匹配包含 cwd；远端工具按完整参数匹配，避免把任意参数一起放行。
- /permissions 查看；/permissions reset 撤销。重启及其他工作区不继承。
- 工作区授权不是 OS 文件沙箱：shell 命令可影响工作区以外路径。弹窗明确标注这一范围，不把 cwd 当作安全隔离。

## 等待与取消

人工审批可以一直等待，其时长从运行时间中扣除并记录 approval_wait 事件。等待同时监听 cancel；取消后停止等待、补齐尚未执行工具的协议结果，不执行稍后返回的批准。弹窗清理由创建者负责，取消 worker 也恢复底层输入。审批 Ctrl+C 可取消任务，Ctrl+Q 可退出。模型等待也监听取消，长时间没有流事件时仍可取消；已收到的部分内容保留。普通模型超时后也可输入下一条指令。

这里不承诺已启动的任意外部命令可即时撤销。已执行动作与待批动作分别处理；取消不是回滚。

## 三种额度

1. 单请求 context_window 默认 1M，分配与借用沿用既有策略。
2. compact_interval_tokens 默认 200k，上次压缩后累计消耗达到 80% 时触发本地压缩；history 占实际容量 80% 时也触发。设置 0 只关闭周期触发。
3. max_run_tokens 默认 1M，是一次 run 的累计输入加输出总预算。压缩不新建 run，不重置累计消耗、时间、步骤、工具次数或权限。

预估普通请求付不起时先压缩重算；仍付不起才执行一次无工具收尾，余额不足则本地暂停。压缩无收益时前移周期基线，避免空转。达到总预算、费用上限或其他运行限制时保留明确停止；/resume 是人为开启新一轮预算，不用于每次压缩。

新增环境变量 VIBE_COMPACT_INTERVAL_TOKENS；VIBE_MAX_RUN_TOKENS 默认改为 1000000。显式环境配置仍优先。没有额外联网摘要请求，工作 history 快照与原始归档继续保留。
