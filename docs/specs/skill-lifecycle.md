# 技能生命周期

日期：2026-10-21。服务于 W1–W3 的可复用编码流程；真实模型使用效果单独验收。

## 行为契约

一个技能是带名称、描述与正文的 Markdown 操作手册。**静态注册保留名称、用途、路径的常驻上下文；动态激活只临时加载正文。** 这是用户对首版语义的明确修正，静态注册不表示把正文永久放入上下文。

目录支持 `<name>/SKILL.md`、`<name>.md` 和三级分类，保留简单 `name:` / `description:` 头及 `---` frontmatter。目录和状态由 Python `SkillManager` 管理，两个 TUI 与 Agent 工具共用。

| 阶段 | 触发 | 模型上下文 |
|---|---|---|
| 发现与注册 | 启动、每次任务开始、`/skills`、`list_skills` | 名称、用途、路径、状态常驻系统分区 |
| 激活 | Agent 按任务选择 `load_skill`，也可 `/skills activate` | 下一次请求加入临时正文 |
| 使用 | 模型按当前技能步骤提出普通工具调用 | 正文不随历史压缩丢失；写入和执行照常审批 |
| 卸载 | 使用结束时 `unload_skill`；每轮结束、暂停、取消或错误统一兜底，也可手动卸载 | 移除临时正文；注册目录和文件继续保留 |

默认发现项目 `.vibe/skills`、`.agents/skills`、`.claude/skills`、`skills`，以及本机 `~/.vibe/skills`、`~/.agents/skills`、`~/.codex/skills`、`~/.claude/skills`。本机只扫描这些标准根，不遍历整个用户目录；支持 `.system` 分类及标准技能根间的符号链接，排除脚本与参考资料目录。

配置默认 `.vibe/skills.json`，`VIBE_SKILLS_CONFIG` 可覆盖；字段为 `paths`、`discover`、`disabled`。`paths` 注册额外来源并优先于项目和本机同名项；`discover: false` 只保留显式来源。相同真实文件重复出现时去重，异源同名诊断。单文件来源只授权该文件，不能扩大为其父目录。`VIBE_SKILLS_HOME` 覆盖本机目录基准，测试使用临时值隔离个人技能。

单文件最多读取 256 KiB，拒绝目录和 FIFO 等非普通文件。激活内容包含元信息最多 64,000 字符，超出时明确拒绝；摘要最多 600 字符。上限修正依据本机 112 份唯一技能文件的大小统计：37 份超过 8 KiB，最大 43,255 字节；原 8k 上限会挡住正常技能。Frontmatter 支持简单标量和 `description` 的 `|` / `>` 多行块，不解析任意 YAML 结构。

旧 `activate` 配置仅兼容为启动临时预装，刷新不重放，首轮结束同样清理；新示例不使用该字段。运行中的激活与卸载不改写注册来源；重启、`--continue` 与下一轮仍有常驻目录，需要正文时重新激活。

## 上下文与权限

技能正文放入可替换的系统片段，并在上下文快照中分别记录 `active_skill` 及文件来源。每轮模型请求同步目录和激活项；管理命令不产生模型调用或任务消息。工具只返回状态回执，防止卸载后正文通过工具历史重新注入。旧版工具正文在模型历史及 `recall` 读取时转换成回执，原始会话日志不改写。

卸载保证停止注入受管理正文，不等于清除此前生成的答案、摘要、执行结果或外部模型的知识。技能不注册任意 Python 函数，不自动运行脚本；实际动作继续使用原有工具和 `ApprovalGate`。

异步技能工具先在候选状态中扫描，只有成功且未取消才提交。扫描线程超时后即使继续结束，也不能迟到激活或改写当前目录。

公共 `Agent.run()` 统一 `finally` 清理临时状态，包含模型循环前的配置错误、消息回调和 trace 回调异常。清理只改内存，不读取配置、不调用模型。请求快照保留实际已发送内容，不在清理时替换本轮回放；下一次请求或显式装载快照会反映清理结果。

## 验证

先用失败测试固定上述行为，再验证配置初始化、运行中新建/修改/删除、激活/卸载、历史压缩、旧会话迁移、越界与损坏输入、Textual/Ink 命令、JSONL 参数校验和拒绝写入。确定性 provider 记录实际发给模型的消息，分别检查正文出现与消失，不以工具返回成功代替上下文验收。

验证命令：`./run_tests.sh -o addopts='' -q`、`npm --prefix tui test`。终端与进程 smoke 使用临时工作区和测试会话，不污染日常会话。

2026-10-21 按用户确认语义修正后验证：Python **729 passed**，Node / Ink **181 passed**。Textual 与 Ink 的真实 120×40 PTY 均完成常驻目录发现 → 临时激活 → 手动卸载 → 重新激活 → 使用 → 自动清理后继续下一轮；两次实际请求快照中的 `active_skill` 分别存在和消失。文件与目录保留，测试会话隔离，退出码为 0，终端模式恢复。记录在 `.vibe/skill-lifecycle/verification.json`。

本机实际发现 88 个可用技能，使用其中 41,883 字符的 `drawio-skill` 正文和确定性 provider 验证：目录先常驻、正文按需进入请求、正常结束后移除、下一轮目录仍在而正文不在。记录在 `.vibe/skill-registry-verification/local-discovery.json`。这些验证不调用真实付费模型，不据此宣称模型已能正确选择并执行全部技能。
