# W4：项目背景复用

日期：2026-10-23。状态：MVP 实现中（读取/注入/Ink 管理）；真实任务价值验收待做。

## 目标

在同一项目开启**新任务**时，复用一份用户可查看、可修改、带来源的项目背景摘要，减少重复交代项目用途、约定和已确认决定。

边界：
- W3 负责续做同一个任务；W4 只服务新任务的项目事实。
- W5 负责个人偏好/画像；W4 不存个人偏好。
- profile 是“摘要 + 来源指针”，不替代 `AGENTS.md` 与项目文档；冲突时以文件为准，Agent 仍应重新读取。

## 存储

- 路径：`<workspace>/.vibe/project-profile.json`，按工作区隔离，不进入版本控制。
- 格式：

```json
{
  "version": 1,
  "entries": [
    {"id": "…", "text": "Ink 是唯一界面入口，core/ 只能依赖标准库", "source": "AGENTS.md", "updated_at": "2026-10-23T00:00:00Z"}
  ]
}
```

- 校验：`version == 1`；`entries` 为数组；`text` 非空字符串；`source` 字符串（默认 `user`）。损坏/缺失时按空背景处理，不阻塞任务。

## 注入

- stdio 后端在**每次 run 前**重新读取当前工作区 profile，因此会话内新增/修改条目会在下一次任务生效。
- 作为独立 system 段：`[PROJECT BACKGROUND]`，逐条带来源，最多 4000 字符；超出时截断并注明。
- 空 profile 不注入；不同 workspace 互相不可见。

## 管理

- Ink `/project`：列出条目（序号、文本、来源）；
- `/project add <文本>`：追加条目，来源记为 `user`；
- `/project remove <序号>`：删除条目；
- 直接编辑 `.vibe/project-profile.json` 亦可；下一次 run 生效。

## 验收

- 同一项目两个不同新任务复用背景，记录少重复的说明；
- 换一个临时工作区，背景不串用；
- 修改/删除条目后，新任务使用新内容，旧内容不再注入；
- 损坏 profile 不阻塞任务。

## 非目标

自动从聊天中提取、向量检索、跨项目共享、个人画像、自动写回事实到文档。
