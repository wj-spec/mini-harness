## 本轮行为

- `run_ink.sh --continue` 打开工作区最近有对话的会话，展示已有消息、任务进度与停止原因；读取压缩快照供模型续做。启动恢复不会自动发模型请求、重放工具或续跑。
- `/resume` 显式开启新一轮预算，先核对实际进度与结果未知的动作。无历史时说明原因，运行中不能并发续做。
- MCP 复用现有 FastMCP 客户端与 ApprovalGate。启动服务与调用工具分别审批；启动等待期间可取消，拒绝或断开不能变成允许；退出回收连接及子进程。
- 审批支持单次允许、精确规则、工作区授权与拒绝。界面只展示后端允许的选项；外部 MCP 不继承原生工具的工作区授权。粘贴文字不能批准。
- `/permissions` 查看本进程权限，`/permissions reset` 撤销当前工作区权限。重启不自动延续授权。
- `/cost` 展示会话累计用量，`/tools` 展示实际注册工具，`/mcp` 展示已加载服务与错误。`/diff` 查看工作区变更，其命令同样经过审批。
- 命令结果区分零退出、非零退出、超时与取消，记录可确认的退出结果与输出；旧记录没有结构化证据时显示未知。工具返回、命令成功与测试通过分别表述。

## 验收与边界

先补失败测试，再实现行为。验证 Python 后端、Node 协议、界面状态与实际本地子进程的连接。覆盖恢复后不自动执行、显式续做、审批范围、权限撤销、MCP 拒绝与退出、失败命令和取消。默认入口保持 Textual 加回归保护。

fake 与本地 MCP 用于确定性接线；真实模型与外部服务联合任务单独验收。运行中纠偏、跨任务记忆与默认入口切换不纳入本切片；W1–W3 的真实任务完成条件仍按里程碑核对。

## 协议增量

沿用 JSONL v1 与 1 MiB 单帧上限。`ready.resumed` 标明恢复，但界面仍等待首个 `status` 后才允许发送任务，避免恢复期间与 MCP 启动审批竞争。`history_message` 逐条传已有消息，不启动运行；`notice` 传恢复摘要、停止原因与 MCP 初始化结果。超大历史仅裁切显示并明确提示，模型快照保持完整。模型工具 ID 保留原值，不误用请求 ID 的 128 字符限制。

`command` 请求接受 `resume / permissions / permissions_reset / cost / tools / diff / mcp`；所有操作串行，重复或忙碌请求拒绝。`resume` 用任务的 `done` 终结，其余用同一请求 ID 的 `command_result` 终结。MCP 初始化用保留 ID `startup`，界面可将其作为取消目标。

`approval_request.decisions` 是当前允许的范围，后端与 Node 都校验审批标识和可选范围，并阻止重复回复。恢复消息和 `tool_result` 可带 `execution`（状态与退出码）；保存在会话、检查点和原文归档中，不作为额外字段发送到模型 API。旧消息没有元数据时不推断退出结果。
