# 工作台体验验收

状态：等待用户实际体验。工程测试和实际 PTY 不能替代本清单的真人确认。

## 启动（无需 Key）

在项目目录运行：

```bash
./start.sh --acceptance
```

> 首次使用与真实任务入口的真人旅程见[交接文档](../openspec/changes/implement-first-run-onboarding/handoff.md)；本文只覆盖工作台体验简化验收。

入口会创建独立的 .vibe/workbench-acceptance/run-* 目录，使用 Demo 模型、虚构配置与两个本地 MCP 服务 alpha / beta。现有 .env、工作目录和 MCP 配置不参与本次验收。依赖已安装时直接启动；缺依赖时沿用启动器安装提示。

启动不会自动连接 MCP；进入后按 /mcp（或“设置 → 外部工具”），对 alpha / beta 选择“重载”发起连接审批，选择“本次允许”。可点击按钮，也可 Tab 选中后 Enter。不要授予整工作区权限，这样能体验后续审批。两个服务只回显测试文本，不访问网络和用户文件。

建议先用常用终端的正常窗口体验一次，再缩小窗口。退出用 Ctrl+Q。再次执行命令会新建一份验收目录；运行记录留在原目录，不自动删除。

## 必验：约 10–15 分钟

### 1. 入门与返回

- [ ] 首页 logo、主操作和提示清楚；不用读 README 也知道可以从哪里开始。
- [ ] 按 Ctrl+T，浏览五个功能区，进入配置帮助 / 设置中心。
- [ ] 退出设置和指引后，原来的 Demo 草稿仍在，没有自动发送。
- [ ] 启动后首页没有自动弹出的 MCP 审批；外部工具显示未连接，可按需连接。
- [ ] 缩小窗口后，当前字段、按钮、审批和返回入口仍能找到。

### 2. 完成一次任务，看结果是否打扰

- [ ] 发送预填的“创建 .vibe/fake-demo.txt 并验证”。
- [ ] 分别允许写文件和检查命令；出现紧凑的“修改 1 个文件 / 检查通过”结果。
- [ ] 能分清正文、审批、结果与工作台记录，不再每轮被“本轮回执”卡打断。
- [ ] 需要细节时能进入检视 / 记录，返回继续输入，阅读位置和草稿符合预期。

### 3. 设置：编辑、保存、应用能否分清

- [ ] /model 打开模型设置；输入虚构 Key（例如 acceptance-test-key），屏幕不显示明文。
- [ ] 点击保存后先拒绝，编辑仍在；再次保存并允许，界面明确说明当前模型未切换。
- [ ] 返回 /settings，把单段步数改为 12，保存，再应用；能分清这两个动作。
- [ ] 按 g 查看目标总预算；能理解“新任务默认”和“已存在任务快照”的区别。
- [ ] 经模型 / 权限子页面返回后，未保存的设置编辑没有丢失。

此环境使用 Demo 模型。连接地址固定为本机关闭端口，模型检测预期失败；不在此处输入真实 Key，也不把 Demo 当作真实模型能力验收。真实服务连接可在后续日常环境中另验。

### 4. MCP：保存不等于重连

打开 /mcp edit，或 /settings 按 m。

- [ ] 默认范围显示“当前”，选择 alpha；能看到 alpha / beta 都已连接。
- [ ] 按 a 进入高级字段；把超时改为 15，保存并允许。
- [ ] alpha 显示“待重载”；beta 仍连接。保存没有自动启动服务。
- [ ] 选择“重载”，审批只针对 alpha。完成后 alpha 不再“待重载”，beta 保持连接。
- [ ] 选择“断开”，界面先确认目标，再经审批；alpha 断开，beta 仍连接。
- [ ] 按 s 能切换“全部 / 当前”；重载、断开之前能看清实际范围。
- [ ] 按“切服务”可选择 beta 和“新增服务”，无需记服务名或命令。

### 5. 错误与离开页面

- [ ] 高级超时填 0 保存，被明确拒绝；输入保留，没有改文件。
- [ ] 改回有效值后可以继续保存，无需重启。
- [ ] 有未保存编辑时离开或切服务，能看懂丢弃确认；Esc 可取消离开。
- [ ] 删除某个服务只删配置，已有连接显示“已删除，仍有连接”；可以单独断开，不误断另一服务。
- [ ] 关闭面板后回到原对话，Ctrl+Q 能正常退出，终端输入正常。
